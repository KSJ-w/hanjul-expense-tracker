# CLAUDE.md — 한줄 가계부 (hanjul-expense-tracker)

> 이 파일은 작업 지원 지침이다. **요구와 시험의 권위는 `docs/` 의 요구 문서에 있다.**
> 여기 적힌 것과 문서가 어긋나면 문서가 이긴다. 구조가 실제로 어떤지는 코드가 이긴다.
>
> **작업을 끝내기 전에 §9 를 반드시 읽는다.** 코드 → TC → 검증 → 문서 역반영 →
> 재검증이 한 작업 단위다. `npm run verify` 가 통과하기 전에는 완료가 아니다.

## 1. 프로젝트 개요

**달력이 중심**인 개인용 가계부. 날짜를 누르면 그날의 팝업에서 수동 기록이 끝나고,
하단 프롬프트에 한 줄 적으면 해석 결과가 확인 팝업으로 뜬다.
**사람이 한 번 확인해야** 기록이 된다. 혼자 쓰는 도구이며 로그인이 없다.
화면은 달력·대시보드·태그·검색·기타 다섯 탭이고, 한 탭은 한 목적만 맡는다(ADR-013).

- Next.js 16 (App Router, Turbopack) · React 19 · TypeScript
- 저장: `node:sqlite`(내장) — 네이티브 빌드가 없다. 파일은 `data/expense.db`
- 화면: HeroUI v3 + Tailwind v4 · 차트: Recharts 3
- 시험: Vitest. TC 대조는 `node test/generate-report.mjs`

## 2. 아키텍처 원칙 (Invariants — 최우선 준수)

다른 규칙과 충돌하면 이것을 먼저 지킨다. 근거는 `docs/sdd/SDD.md` §2다.

1. **외부로 나가는 호출은 `src/lib/interpret/gemini.ts` 에만 존재한다.**
   다른 어디에도 `fetch` 를 쓰지 않는다. `test/boundary.test.ts` 가 소스를 훑어 검사한다.
   여기를 어기면 `FR-ENTRY-15`(해석 외 전송 금지)를 판정할 근거가 사라진다.
2. **확정 기록은 `createRecord()` 를 거쳐서만 생긴다.** 후보(`candidates`)와 기록(`records`)은
   다른 표다. 확인 동작 없이 `records` 에 넣는 경로를 만들지 않는다(`FR-ENTRY-05`).
3. **집계·조회는 `records` 만 읽는다.** 후보를 합계에 넣지 않는다. 모든 조회에
   `deleted_at IS NULL` 이 붙는다.
4. **분류 삭제는 보관 처리다.** `categories.archived_at` 을 채울 뿐 행을 지우지 않는다.
   행을 지우면 그 분류에 속했던 기록의 귀속이 끊겨 `NFR-CAT-01` 이 깨진다.
5. **자동 배정 분류는 언제나 사용자 분류 집합의 원소다.** 없는 분류를 만들어 붙이지
   않는다. 마땅한 것이 없으면 `null`(미확정)로 둔다(`FR-CAT-06`).
6. **빈 결과를 부재로 표시하지 않는다.** "찾지 못함"과 "없었음"은 다르다(`FR-VIEW-07`).
   조회 함수는 `{ items, noMatch }` 를 돌려주고 화면은 `EmptyNote` 를 쓴다.
   `EmptyNote` 는 **기록**이 없다고만 말한다 — 거래가 없었다고 말하지 않는다.
   설명 문장이 아니라 낱말이 그 구분을 지킨다.

## 4. 코딩 규칙

- **저장소 함수는 마지막 인자로 `db: DatabaseSync = getDb()` 를 받는다.** 시험이 임시 DB 를
  넘길 수 있어야 한다. 이 규칙을 어기면 그 함수는 시험할 수 없다.
- **실패를 예외로 던지지 않는다.** `{ ok: false, reason }` 을 돌려준다. 화면이 사용자에게
  무슨 일이 있었는지 말해야 하므로, 사유가 타입으로 남아야 한다.
- **날짜에 `toISOString()` 을 쓰지 않는다.** UTC 로 바뀌어 한국 시간대에서 하루 밀린다.
  `toISODate()` 를 쓴다.
- **금액은 정수(원)다.** 부동소수를 쓰지 않는다.
- 사용자에게 보이는 문구는 한국어로, "찾지 못했다"와 "없었다"를 섞지 않는다.
- 주석은 "무엇을"이 아니라 **"왜 이렇게 했는가"**를 적는다. 특히 요구 번호를 남긴다.

## 5. 계약 표

| 표면 | 무엇 | 비고 |
|---|---|---|
| `stageFromInput(text, imageDataUrl?)` | 입력 → 기록 후보 세우기 | 확정하지 않는다 |
| `confirmCandidateAction(id)` | 후보 → 확정 기록 | 미확정 항목 있으면 실패 사유로 알린다 |
| `GET /api/export?images=0\|1` | 반출 묶음(JSON) | 기본은 이미지 포함(NFR-VIEW-03) |
| `GET /api/export/csv` | 표 계산용 CSV | **복원용이 아니다** |
| `GET /api/image/[id]` | 근거 이미지 | 기기 안 파일을 돌려줄 뿐 |
| 라우트 | `/`(달력) · `/dashboard` · `/tags` · `/search` · `/etc` | 탭을 늘리거나 줄이기 전에 ADR-013 을 먼저 고친다 |
| 예산 | `repo/budgets` · `setBudgetAction` | 화면은 ADR-014 로 내렸다. 계층은 살아 있고 `FR-VIEW-08`·`FR-VIEW-09` 도 유효하다 |
| `InterpretProvider` | 해석 수단 계약 | 새 수단은 이것만 구현하고 `PROVIDERS` 에 넣는다 |

## 7. 정책·결정 로그

되돌려지면 안 되는 결정과, **이미 반증된 대안**이다. 전체는 `docs/sdd/SDD.md` §3(ADR).

- **차트 색을 SVG 속성에 `var(--token)` 으로 넘기지 않는다.**
  SVG 의 `fill` 은 CSS 속성이 아니라 XML 속성이라 `var()` 를 해석하지 못한다.
  축과 범례는 나오는데 도형만 안 보이는 증상으로 나타난다(실제로 겪음).
  `Charts.tsx` 의 `useTokens()` 가 실행 시점에 실제 색으로 풀어 준다.
- **Recharts 의 `<Pie>` 반지름에 퍼센트 문자열을 쓰지 않는다.**
  `innerRadius="58%"` 는 v3 에서 섹터가 비어 렌더된다. 숫자를 쓴다(실제로 겪음).
- **수입과 지출을 한 축에 그리지 않는다.** 월급(320만)과 식비(6만)를 같은 눈금에 두면
  작은 쪽이 사실상 보이지 않는다. 축을 나눈다.
- **`I18nProvider` 는 클라이언트 경계 안에 둔다.** 컨텍스트를 쓰므로 서버 컴포넌트에서
  import 하면 전체가 500 이 된다(실제로 겪음). `src/app/providers.tsx` 참조.
- **부모가 넘긴 배열을 `useEffect` 로 state 에 복사하지 않는다.** 배열은 매 렌더
  새 참조라 의존성이 매번 바뀌어 렌더가 무한히 반복된다. 화면이 "렌더 미완료"로
  멈추는 증상으로 나타난다(실제로 겪음). 처리한 것은 **id 집합**으로 기억한다 —
  `CandidateDialog` 참조.
- **달력 칸에 `<button>` 을 쓸 때 `flex flex-col` 을 준다.** 브라우저는 버튼의 내용을
  버튼이 내용보다 클 때 **세로 가운데로 민다.** `text-left` 만으로는 가로만 잡히고,
  날짜 숫자가 칸 한복판에 떠서 달력으로 읽히지 않는다(실제로 겪음).
- **탭 밑줄을 `-bottom-px` 로 컨테이너 밖에 걸치지 않는다.** 넘친 1px 때문에
  `overflow-x-auto` 가 세로 스크롤바까지 만들어 탭 줄 오른쪽에 15px 짜리 회색 띠가
  생긴다(실제로 겪음, `scrollHeight 41 > clientHeight 40` 으로 확인). `bottom-0` 을 쓴다.
- **네이티브 `<dialog>` 에 `m-auto` 를 명시한다.** 리셋이 margin 을 0 으로 만들어
  두면 팝업이 좌상단에 붙는다. `backdrop:bg-transparent` 를 주면 전역 backdrop 이
  덮여 배경이 흐려지지 않는다(둘 다 실제로 겪음).
- **다건 입력의 방향은 조각별로 판정한다.** 문장 전체를 보면 뒤쪽의 "받았어"가
  앞의 지출까지 수입으로 만든다(실제로 겪음, TC-ENTRY-46).
- **개발 서버가 도는 중에 `.next` 를 지우지 않는다.** Turbopack 캐시가 깨져
  서버가 패닉으로 죽는다. 서버를 먼저 멈춘다(실제로 겪음).
- **응답 스키마의 `enum` 에 빈 문자열을 넣지 않는다.** `enum: ['income','expense','']`
  는 `HTTP 400 enum[2]: cannot be empty` 로 거부된다(실제로 겪음). '모름'은 빈 값이
  아니라 **required 에서 빼서 항목을 생략**하는 것으로 표현한다.
- **기본 모델은 `gemini-3.6-flash` 다. `gemini-2.5-flash` 를 쓰지 않는다.**
  모델 목록 조회에는 나오지만 **새로 발급한 키로 호출하면 404** 다
  ("no longer available to new users"). 그 응답이 후속으로 지목한 것이 3.6-flash 이며,
  이 키로 `countTokens` 가 200 을 돌려주는 것을 확인했다(실제로 겪음).
- **외부 호출 실패를 조용히 삼키지 않는다.** 전에는 `catch` 가 사유를 버려서
  폴백은 됐지만 원인을 아무 데서도 알 수 없었다. `gemini.ts` 의 `fail()` 이
  서버 로그에 남기고 `failureDetail` 로 화면까지 올린다(실제로 겪음).
- **`better-sqlite3` 를 쓰지 않는다.** Windows 에서 네이티브 빌드가 필요하다.
  Node 24 의 `node:sqlite` 로 충분하다.
- **기본 분류는 "분류가 하나도 없을 때만" 넣는다.** 사용자가 전부 지운 상태를 되돌리면
  `FR-CAT-03` 이 무의미해진다.

## 8. 보안 규칙

- `data/` 와 `.env*` 는 커밋하지 않는다. 사용자의 가계 기록과 API 키가 들어간다.
- `GEMINI_API_KEY` 는 서버에서만 읽는다. 클라이언트 번들에 넣지 않는다.
- 외부로 나가는 것을 늘리려면 먼저 `docs/` 의 `FR-ENTRY-15`·`FR-ENTRY-16` 을 고친다.
  코드부터 고치면 사용자에게 보여 주는 "나가는 항목" 목록과 실제가 어긋난다.

## 9. 작업 단위를 끝내는 절차 (건너뛰지 않는다)

> **이 절은 참고가 아니라 순서다.** 아래 5단계를 마치기 전에는 어떤 작업도
> "끝났다"고 말하지 않는다. 실제로 이 순서를 어겨 본 적이 있다 —
> 코드를 끝내고 완료 보고를 한 뒤에야 ADR 을 채웠고, 그동안 문서는 코드가 이미
> 버린 결정(ADR-003 의 "규칙 기반 기각")을 사실처럼 말하고 있었다.

### 순서

1. **코드를 쓴다.**
2. **TC 를 쓴다.** 새 동작이면 `docs/tc/TC_*.md` 에 TC 를 **먼저** 정의하고,
   테스트 이름에 `[TC-<COMP>-NN]` 을 태깅한다. TC 없이 테스트를 늘리지 않는다.
3. **검증한다.** `npm run verify` — 타입·시험·TC 대조·문서 드리프트를 한 번에 본다.
4. **문서를 역반영한다.** 아래 표대로. 영향이 닿는 **가장 상위 문서부터** 내려온다
   (요구가 새로 생겼으면 RFP 부터, 보장 수준만 달라졌으면 SRS 부터).
   고친 문서는 **버전을 올리고 변경 이력에 한 줄 남긴다.**
   하위 문서의 `기준 문서` 버전 표기도 같이 올린다 — 이것이 가장 자주 빠진다.
5. **다시 `npm run verify`.** 통과해야 끝이다. 그다음에 완료를 말한다.

### 무엇을 역반영하는가

| 무슨 일이 있었나 | 같이 갱신할 것 |
|---|---|
| 동작·정책이 바뀜 | 해당 `FR`/`NFR` + `docs/tc/TC_*.md` + 추적성 표 |
| 없던 요구가 필요해짐 | **RFP 에 다음 빈 번호를 먼저 발급** → PRD → SRS → TC 순으로 내린다 |
| 설계 선택을 바꿈 / 새로 정함 | `docs/sdd/SDD.md` ADR 에 **행을 더한다.** 기존 행은 지우지 않고 `Superseded(→ADR-0NN)` 로 남긴다 |
| 구현하다 요구끼리 충돌을 발견 | 코드로 우회하지 말고 **문서를 먼저 고친다.** 충돌을 발견한 사실 자체를 ADR 의 선택 이유에 적는다 |
| 미결이 풀림 | 소유 문서의 미결 표를 `Decided` 로 바꾸고 **반영 위치를 연결**한다 |
| 새 API·서버 액션 | 이 파일 §5 계약 표 |
| 구현하며 겪은 함정 | 이 파일 §7 정책 로그 (요구가 아니라 컨텍스트다) |
| 수치 합격선 | **SRS §3 만 소유한다.** TC 는 인용만 한다 |
