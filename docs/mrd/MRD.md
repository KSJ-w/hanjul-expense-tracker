## 1. 문서 목적

이 문서는 아래 질문에 답한다.

- 가계부를 쓰려는 사람은 어떤 문제를 반복해서 겪는가
- 그 문제를 지금은 어떻게 해결하고 있으며 무엇이 부족한가
- 이 제품이 무엇을 우선하고 무엇을 약속하지 않는가
- 성공했는지를 나중에 무엇으로 확인할 것인가

답하지 않는 것은 다음 문서가 맡는다.

| 답하지 않는 것 | 소유 문서 |
|---|---|
| 이번 개발에서 무엇을 요구하는가 (FR·NFR) | RFP |
| 사용자가 어떤 경험을 얻는가 (스토리·수용 조건) | PRD |
| 무엇을 얼마나 정확히 보장하는가 (검증 가능 요구·합격선) | SRS |
| 어떻게 구현하는가 (구조·설계 결정) | SDD |
| 충족을 어떻게 증명하는가 (시험 절차) | TC |

## 2. 문제 정의

**가계부는 시작하지 못해서가 아니라 이어가지 못해서 실패한다.**

마크로밀엠브레인 트렌드모니터의 소비자 조사에 따르면, 가계부를 현재 작성하는
사람은 33.6%인 반면 **과거에 작성하다가 중단한 사람은 45.4%로 더 많았다**.
작성 경험이 아예 없는 사람은 21.0%였다[^1]. 즉 다수는 가계부를 몰라서 안 쓰는
것이 아니라, 써 보고 그만둔 사람들이다.

그만두는 이유의 첫머리에 있는 것은 능력이나 의지가 아니라 **번거로움**이다. 같은 조사에서
가계부를 쓰지 않는 이유로 "귀찮아서"가 58.0%로 가장 높았고, "익숙하지 않아서"가
40.5%였다[^1]. 같은 원자료를 분석한 학술 연구는 가계부를 작성하는 집단이
충동구매 비율이 낮고 가정생활로 인한 정신적 피로 점수도 낮게 나타났다고
보고한다[^2] — **효과가 없어서 그만두는 것이 아니라, 효과에 도달하기 전에
그만두는 것이다.**

### 현재 방식과 그 병목

- **손으로 적는 방식** — 가계부 작성자 중 수기형이 42.6%로 가장 많고, 인터넷
  전자가계부 31.3%, 스마트폰 앱 26.2%가 뒤를 이었다[^1]. 어느 쪽이든 한 건을
  남기려면 날짜·금액·분류·수입인지 지출인지를 사람이 나눠서 채워야 한다. 기록
  한 건의 비용이 작지 않아, 며칠 밀리면 밀린 것을 되짚는 비용이 다시 기록을
  막는다.
- **금융기관 연동에 기대는 방식** — 결제 내역이 자동으로 들어오지만, 이 방식은
  허가받은 사업자만 제공할 수 있다[^5]. 개인이 만드는 도구에는 애초에 열려 있지
  않은 길이다(§6.1). 또한 자동으로 들어온 내역의 분류가 쓰는 사람의 기준과
  얼마나 어긋나는지, 그래서 분류를 고치는 일이 얼마나 남는지는 확인하지
  못했다 `[확인 필요]` — 연동형 서비스 사용자가 분류를 얼마나 자주 손대는지에
  대한 공개 자료를 찾지 못했다. 실제 사용 기록으로 확인해야 한다.
- **자동으로 들어오지 않는 지출이 남는다** — 한국은행 조사를 인용한 보도에 따르면
  2024년 지급수단 중 현금 이용 비중은 건수 기준 15.9%였고, 대면 거래에서 현금을
  써 본 경험은 88.0%였다[^3][^4]. 현금 이용 비중이 곧 미기록 비율은 아니므로
  이는 대리 지표이며(현금 거래가 곧 기록 누락이라는 조사는 확보하지 못했다),
  "연동만 켜 두면 저절로 채워진다"가 성립하지 않는다는 정도까지만 말한다.
- **표 계산 도구로 직접 관리하는 방식** — 분류를 마음대로 정할 수 있는 대신
  기록·집계·요약의 형식을 사람이 전부 설계하고 유지해야 한다. 그 유지 비용이 곧
  중단 사유가 된다.

**핵심 필요는 "더 정교한 분석"이 아니라 "기록 한 건을 남기는 비용"에 있다.**
분석은 기록이 쌓인 다음의 이야기이고, 지금 끊기는 지점은 기록이다.

## 3. 대상 사용자와 맥락

### 3.1 직접 사용자

| 사용자 | 수행하는 일 |
|---|---|
| 가계부 작성자(본인) | 그날그날의 지출·수입을 남기고, 자신의 기준으로 분류를 만들고 고치고, 기간별로 되짚어 본다 |

이 제품은 한 사람이 자신의 기록을 남기기 위해 쓰는 도구다. 역할 구분이나 권한
분리가 필요한 다수 사용자 상황은 대상이 아니다(§5.2).

### 3.2 제품 밖 이해관계자

제품을 사용하는 역할이 아니며, 제품 안에 자리를 갖지 않는다.

| 이해관계자 | 제품과의 관계 |
|---|---|
| 외부 인공지능 서비스 사업자 | 사용자가 적은 문장·이미지의 해석을 맡는 위치. 이용 조건과 한도를 일방적으로 정한다 |
| 개인정보 감독기관 | 개인정보 처리 기준을 제시한다[^7]. 제품이 배포 형태로 바뀌면 적용 전제가 달라진다(§6.1) |
| 금융 감독기관 | 금융기관 연동 방식의 진입 자체를 허가로 통제한다[^5] |

## 4. 제품 방향

기록을 남기는 데 드는 비용을 사람이 감당하지 않게 만든다. 사람은 무슨 일이
있었는지를 자기 말로 한 번 적고, 그 말을 기록의 형태로 바꾸는 일은 제품이 한다.
사람에게 남는 일은 **"이렇게 적으면 되겠습니까"에 대한 확인**뿐이다. 그렇게
기록이 이어지면, 되짚어 보는 일은 그 다음에 가능해진다.

**핵심 원칙**

1. **기록의 마찰을 가장 먼저 줄인다.** 다른 어떤 가치와 충돌해도 이것을 먼저
   지킨다. 기록이 끊기면 나머지는 성립하지 않는다.
2. **자동 해석은 제안이지 확정이 아니다.** 사람이 확인하기 전에 기록을 확정하지
   않는다. 틀린 기록이 쌓이면 되짚어 보는 일 자체가 무의미해진다.
3. **자동이 실패해도 길이 끊기지 않는다.** 해석이 안 되거나 반만 될 때, 사람이
   손으로 끝까지 갈 수 있는 길이 항상 열려 있어야 한다.
4. **분류는 사용자의 것이다.** 제품이 정한 분류 체계를 강요하지 않는다. 남이
   정한 분류로 들어온 기록을 내 기준으로 옮기는 일 자체가 새로운 번거로움이다.
5. **처음 열었을 때 무엇을 하는 도구인지 알 수 있어야 한다.** 무엇부터 해야
   할지 배워야 하는 도구는 시작 단계에서 이미 마찰을 만든다.
6. **밖으로 나가는 것은 최소한으로 한다.** 해석에 필요하지 않은 것은 내보내지
   않고, 무엇이 나가는지 사용자가 알 수 있어야 한다.
7. **기록은 사용자의 손에 남는다.** 특정 사업자의 서비스가 멈추거나 조건을
   바꿔도 지금까지의 기록이 사라지지 않아야 한다.

## 5. 범위와 비범위

### 5.1 범위

| 범위 | 제공해야 하는 결과 |
|---|---|
| 자연어 문장으로부터의 기록 생성 | 사람이 자기 말로 적은 지출·수입이 날짜·금액·분류·수입인지 지출인지의 구분을 갖춘 기록으로 남는다 |
| 한 번에 여러 건의 기록 | 한 번에 여러 건을 적어도 각각 별개의 기록으로 남는다 |
| 이미지로부터의 기록 생성 | 영수증·결제 내역 이미지가 위와 같은 형태의 기록으로 남는다 |
| 사람의 확인 | 자동 해석의 결과는 사용자의 확인을 거쳐 확정된다 |
| 해석 실패 지점에서의 이어받기 | 해석이 안 되거나 일부만 됐을 때, 사람이 그 지점에서 이어서 기록을 완성할 수 있다 |
| 손으로 하는 기록·수정·삭제 | 자동 해석 없이도 기록을 처음부터 만들고 고치고 지울 수 있으며, 잘못 지운 기록을 되살릴 수 있다 |
| 사용자 정의 분류 | 사용자가 자신의 분류 체계를 만들고 유지한다. 처음부터 비어 있는 상태로 시작하지 않는다 |
| 고친 분류의 반영 | 사용자가 한번 고쳐 둔 분류가 이후 같은 성격의 입력에 반영된다 |
| 날짜 단위 조회 | 어느 날 무엇이 있었는지를 날짜를 기준으로 되짚을 수 있다 |
| 조건을 걸어 되짚기 | 기간·분류·금액·수입인지 지출인지·적은 내용으로 지난 기록을 찾을 수 있다. 조건을 칸마다 고르는 대신 **찾고 싶은 것을 자기 말로 한 줄 적어도** 같은 결과에 닿는다 — 기록을 남기는 길이 한 줄인데 찾는 길만 칸 여럿이면 같은 제품이 두 얼굴을 갖는다 |
| 기간별 요약 | 주·월·연 단위로 수입과 지출의 크기와 구성이 한눈에 들어온다 |
| 예산 대비 확인 | 스스로 정한 한도와 실제 지출을 견줄 수 있다 |
| 반복되는 지출·수입의 처리 | 매달 같은 항목을 매번 다시 적지 않아도 된다 |
| 근거 이미지의 보관 | 기록의 출처가 된 이미지를 나중에 다시 확인할 수 있다 |
| 기록의 반출과 반입 | 기록을 파일로 내보내고 다시 들여올 수 있다 |

### 5.2 비범위

이번에 **약속하지 않는 것**이다. 열등해서가 아니라 이번 범위가 아니기 때문이다.

- 자연어를 통한 수정·삭제·설정 변경 — 자연어는 기록을 **남기고 찾는** 데만 쓴다.
  적은 말이 기록을 바꾸는 길은 두지 않는다. 오해석이 곧 자료의 훼손이 되기 때문이다
  (조회는 v0.7 에서 범위로 옮겼다 — §5.1 '조건을 걸어 되짚기')
- 금융기관 계좌·카드의 자동 연동과 거래 내역 수집 (§6.1의 법적 제약)
- 여러 사용자, 계정·로그인, 가족·부부 공유
- 모바일 전용 애플리케이션
- 외화 표기와 환산, 한국어 외 언어
- 투자·부동산·순자산 관리
- 계좌·결제수단별 잔액 추적
- 세무 신고용 자료 생성

## 6. 제약

### 6.1 법적 제약

- **금융기관 자동 연동은 진입 자체가 통제된다.** 「신용정보의 이용 및 보호에 관한
  법률」 제4조는 본인신용정보관리업을 하려는 자는 금융위원회의 허가를 받아야
  하며, 허가 없이 이를 해서는 안 된다고 정한다[^5]. 개인이 만드는 도구가 선택할
  수 있는 길이 아니다 — 이 제약이 §5.2의 비범위를 강제한다.
- **개인 용도와 배포는 전제가 다르다.** 「개인정보 보호법」 제2조 제5호는
  개인정보처리자를 "업무를 목적으로" 개인정보파일을 운용하기 위하여 개인정보를
  처리하는 자로 정의한다[^6]. 혼자 자기 기록만 남기는 동안과, 다른 사람이 쓰도록
  내보내는 순간은 적용 전제가 달라진다. 배포는 이번 범위 밖이지만, 전제가 바뀔 수
  있다는 점을 요구가 미리 알고 있어야 한다.
- **외부 인공지능 서비스에 개인정보를 넘기는 처리에는 감독기관이 제시한 기준이
  있다.** 개인정보보호위원회는 생성형 인공지능의 개발·활용 전 단계에 대한 개인정보
  처리 기준을 안내서로 제시하고 있다[^7].

### 6.2 운영 제약

- 혼자 만들고 혼자 유지한다. 유지 인력이 늘어나지 않으므로, 사람 손이 계속 가야
  하는 방식은 선택지가 아니다.
- 비용을 들이지 않는 조건에서 시작한다. 무료로 제공되는 외부 인공지능 서비스는
  사용 한도와 이용 조건을 사업자가 바꿀 수 있고 사용자는 이를 통제할 수 없다.
  특정 사업자에 묶이면 그 변경이 곧 제품의 중단이 된다.

### 6.3 기술적 제약

- 자연어와 이미지의 자동 해석은 확률적이다. 언제나 옳은 해석은 존재하지 않으며,
  완전한 정확도를 전제로 한 제품은 성립할 수 없다.
- 외부 서비스에 해석을 맡기는 동안에는 연결이 끊기면 해석이 불가능하다. 해석이
  불가능한 시간이 곧 기록이 불가능한 시간이 되는지는 제품이 어떻게 짜이느냐에
  달려 있다.
- 자동 해석이 실제로 어느 수준까지 맞는지는 아직 확인되지 않았다 `[확인 필요]` —
  실제 입력 표본으로 측정해 `docs/report/`에 남긴 뒤에야 알 수 있다.

### 6.4 도입자가 별도로 확정해야 하는 사항

- 어떤 외부 인공지능 서비스를 쓸 것인가, 그 사업자의 이용 조건이 개인의 가계
  기록을 다루는 용도에 부합하는가
- 해석을 위해 무엇까지 밖으로 내보낼 것인가의 경계 — §10 M-03 에서 확정했다.
  이미지는 가공 없이 보내되 첨부 시점에 그 사실과 가릴 수 있다는 안내를 붙이고,
  나가는 항목의 종류를 사용자가 볼 수 있게 한다

## 7. 성공 결과

측정 데이터가 없는 시점이므로 목표 수치를 만들지 않는다. 나중에 무엇으로 확인할
것인지만 질문으로 고정한다.

| 성과 질문 | 확인할 결과 |
|---|---|
| 기록이 이어지는가 | 쓰기 시작한 뒤 기록이 끊긴 기간이 어떻게 변하는가 |
| 한 줄로 적는 것이 손으로 넣는 것보다 실제로 덜 번거로운가 | 같은 내용을 두 방식으로 남길 때 드는 수고의 비교 |
| 자동 해석의 결과를 사람이 얼마나 고쳐야 하는가 | 확인 단계에서 사람이 손대는 항목이 무엇이며 시간이 지나며 어떻게 달라지는가 |
| 처음 열었을 때 무엇을 하는 도구인지 알 수 있는가 | 배우는 과정 없이 첫 기록에 도달하는지 관찰 |
| 기록이 되짚어 보는 일로 이어지는가 | 기록만 남기고 마는지, 기간별 요약을 실제로 열어 보는지 |
| 분류가 사용자의 기준으로 유지되는가 | 처음 만든 분류가 계속 쓰이는지, 매번 고쳐 넣게 되는지 |
| 기록을 잃을 걱정 없이 쓸 수 있는가 | 반출한 기록만으로 되살릴 수 있는지 |
