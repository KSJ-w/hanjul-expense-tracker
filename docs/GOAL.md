# GOAL — 한줄 가계부

> 작성자: 사용자 · 정리: 2026-09-08 · 상태: 확정(질의응답 완료)
>
> 이 문서는 문서 체인(MRD→RFP→PRD→SRS→TC) **밖의 입력물**이다.
> 만들고 싶은 것을 자유롭게 적은 것이며, MRD가 완성되면 역할이 끝난다.
> 여기 적힌 것은 요구가 아니라 **의도**다. 근거와 검증은 하위 문서가 맡는다.

---

## 1. 한 줄 요약

말하듯 한 줄 적거나 영수증 사진 한 장만 주면, 알아서 분류·날짜·수입/지출을 채워
기록해 주고, 달력과 대시보드로 돈의 흐름을 보여 주는 **개인용 가계부 웹**.

## 2. 왜 만드는가

가계부는 "쓰기 귀찮아서" 실패한다. 금액·분류·날짜를 매번 폼에 나눠 넣는 순간
기록이 끊기고, 기록이 끊기면 분석은 아무 의미가 없다.
**입력의 마찰을 0에 가깝게 만드는 것**이 이 프로젝트의 전부다.

## 3. 핵심 아이디어

- **입력은 자연어 한 줄로** — "어제 점심 김밥천국 8000원", "월급 300만원 들어옴"
- **이미지도 입력** — 영수증 사진, 결제 알림 캡처, 카드 내역 캡처
- **알아서 채운다** — 내가 만들어 둔 분류 중 하나로 배정하고, 수입/지출을 구분하고,
  "어제·지난주 금요일·3일 전" 같은 자연어 날짜를 실제 날짜로 해석해 그 날에 넣는다
- **보는 것은 달력과 대시보드로** — 달력에서 하루하루를, 대시보드에서 이번 주·이번 달·
  올해를 여러 그래프로

## 4. 사용자가 느껴야 할 것

- 첫 화면을 보자마자 **"이건 가계부구나, 여기 쓰면 되는구나"** 를 안다.
  뭘 해야 할지 모르겠는 막막한 화면은 실패다.
- 메인 하단에 프롬프트 입력창이 있고, 거기 치면 기록된다. 그게 **주 동선**이다.
- 자연어가 유일한 길은 아니다. **수동 입력 폼도 항상 있다.**
  자연어가 틀렸을 때, 세밀하게 넣고 싶을 때 돌아갈 곳이 있어야 한다.
- 기능이 늘어도 화면은 단순해야 한다. 깔끔하고, 명확하고, 복잡하지 않게.

## 5. 결정 사항

질의응답으로 확정한 방향이다. 여기서 벗어나는 설계는 다시 물어야 한다.

| # | 항목 | 결정 | 이유 |
|---|---|---|---|
| D-01 | 자연어의 사정거리 | **기록 입력만** 자연어로 받는다 | 조회·수정·삭제·설정까지 열면 오해석이 데이터를 망가뜨리고, 화면이 "뭘 물어봐야 하지?" 하는 막막한 채팅창이 된다. 조회·수정·분석은 달력·목록·대시보드라는 **명확한 UI**가 맡는다 |
| D-02 | 사용 대상 | **나 혼자, 로그인 없음** | 단일 사용자 개인 도구. 계정·권한·공유 없음 |
| D-03 | 데이터 저장 | **로컬 DB (SQLite)** | 내 기기 안에 파일로. 별도 서버·클라우드 계정 없이 시작 |
| D-04 | 기술 스택 | **Next.js + SQLite** | 프론트/백엔드 한 프로젝트. API 키를 서버 쪽에 숨길 수 있고, 나중에 클라우드로 옮기기 쉽다 |
| D-05 | AI 처리 | **Gemini 무료 티어 기본, 제공자 교체 가능한 구조** | 무료 티어 중 **이미지(영수증) 입력까지 되는 건 사실상 Gemini뿐**. 다만 무료 한도가 수시로 바뀌고 프라이버시 조건이 붙으므로, 제공자를 갈아끼울 수 있는 경계를 처음부터 둔다 |
| D-06 | 프라이버시 | **보내되 최소화** | 해석에 필요한 것만 외부로 보낸다. 무엇이 나가는지 사용자가 알 수 있어야 하고, **영수증 원본 이미지는 로컬에만 보관**한다 |
| D-07 | 확인 단계 | **확인 카드 후 저장** | 해석 결과(날짜·금액·분류·수입/지출)를 카드로 보여 주고 한 번 눌러 저장. 틀린 기록이 쌓이는 것을 막는다 |
| D-08 | 화면 우선순위 | **데스크톱 우선** | PC 브라우저에서 넓게 보며 쓴다. 모바일은 나중 |
| D-09 | 실행 환경 | **로컬 실행으로 시작, 나중에 배포 가능하도록** | 지금은 localhost. 다만 나중에 폰에서도 쓰게 배포할 여지를 남긴다 |
| D-10 | 성공의 모습 | **한 줄 입력 → 정확한 기록** | 이것이 되면 나머지가 의미를 갖는다. 이게 안 되면 나머지는 다 장식이다 |
| D-11 | 통화·언어 | **원화(KRW) · 한국어** | 다중 통화·다국어는 범위 밖 |

### AI 제공자 조사 근거 (D-05)

2026년 9월 기준, 카드 없이 쓸 수 있는 무료 LLM API 비교:

| 제공자 | 무료 한도 | 이미지 입력 | 학습에 사용 |
|---|---|---|---|
| **Gemini (AI Studio)** | 모델별 20–1,500 req/day | **가능** | 사용됨 (EU/UK/EEA 외) |
| Groq | 30 RPM / 1,000 req/day | 불가 | 사용 안 함 |
| Mistral | ~1B tok/월 (Experiment) | 불가 | 사용됨 (동의 필수) |
| OpenRouter | 20 RPM / 50 req/day | 모델에 따라 | 사용 안 함 |
| Cerebras | 30 RPM / ~1M tok/day | 불가 | 사용 안 함 |

개인 가계부는 하루 수십 건 수준이라 무료 한도로 충분하다. 영수증 이미지까지
한 모델로 처리할 수 있는 곳이 Gemini뿐이라 이것을 기본값으로 한다.
한도·정책이 바뀌거나 프라이버시가 걸리면 유료 API나 로컬 모델로 바꿀 수 있어야 한다.

## 6. 있어야 하는 것 (사용자 언어로)

### 6.1 기록

- 자연어 한 줄 입력 → 해석 → **확인 카드** → 저장
- 한 번에 여러 건 입력 ("점심 8000원, 커피 4500원")
- 영수증/캡처 이미지 입력 → 해석 → 확인 카드 → 저장
- **수동 입력 폼** — 자연어 없이도 처음부터 끝까지 넣을 수 있다
- 해석이 실패하거나 일부만 됐을 때, 그 상태 그대로 수동 폼으로 이어받는다
- 기록 수정·삭제, 방금 한 일 되돌리기

### 6.2 분류(카테고리)

- 분류를 직접 추가·수정·삭제·순서 변경
- 처음 켰을 때 쓸 만한 **기본 분류 세트**가 미리 있다 (빈 화면에서 시작하지 않는다)
- 수입 분류와 지출 분류를 구분
- 내가 고친 분류를 기억해서, 다음에 같은 가게·같은 표현이 오면 그 분류로 배정

### 6.3 보기

- **달력 뷰** — 날짜별 내역, 일별 합계, 월 이동
- **대시보드** — 이번 주 / 이번 달 / 올해, 여러 형태의 그래프
  (기간별 추이, 분류별 비중, 수입 대비 지출, 전 기간 대비 비교)
- **목록 뷰** — 기간·분류·금액·키워드로 검색하고 걸러 보기
- 수입·지출·잔여의 합계가 항상 보인다

### 6.4 그 외 (사용자가 고른 것)

- **예산/목표 관리** — 분류별·월별 예산을 정하고 얼마 썼는지 대비해서 보여 준다
- **반복 거래** — 구독·월세처럼 매달 반복되는 항목을 등록해 두면 자동으로 들어간다
- **영수증 원본 보관** — 올린 이미지를 해당 내역에 붙여 두고 나중에 다시 볼 수 있다
- **CSV 가져오기 / 내보내기** — 백업, 다른 도구로 옮기기, 기존 내역 한꺼번에 넣기

## 7. 만들지 않는 것 (지금은)

실패가 아니라 **약속**이다. 필요해지면 그때 GOAL을 고친다.

- 자연어로 조회·수정·삭제·설정 변경 (D-01)
- 은행·카드사 자동 연동 / 스크래핑
- 여러 사용자, 로그인, 가족 공유
- 모바일 앱 (웹만)
- 다중 통화, 다국어
- 투자·자산·순자산 관리
- 결제수단·계좌별 잔액 관리 (일단 범위 밖 — 필요해지면 재검토)

## 8. 아직 열려 있는 것

하위 문서(MRD 이후)에서 조사·결정할 것들. 지금 답을 지어내지 않는다.

| ID | 질문 |
|---|---|
| Q-01 | 자연어 해석이 "정확하다"의 기준은 무엇인가 — 어느 정도 맞아야 쓸 만한 것으로 치는가 |
| Q-02 | 확인 카드를 매번 눌러야 한다면, 그것이 "마찰 0"이라는 목표와 충돌하지는 않는가 |
| Q-03 | Gemini 무료 한도를 넘겼을 때 사용자에게 무엇을 보여 주고 어떻게 넘어가는가 |
| Q-04 | 영수증에 담긴 카드 뒷자리·상호·시각 중 무엇까지 외부로 보내야 해석이 되는가 (D-06의 "최소화"의 실제 선) |
| Q-05 | 이미지 원본을 로컬 어디에 어떤 형태로 보관하고, 용량이 커지면 어떻게 하는가 |
| Q-06 | 기본 분류 세트는 무엇으로 시작하는가 |
| Q-07 | 반복 거래는 자동으로 넣는가, 넣기 전에 확인을 받는가 |
| Q-08 | 나중에 배포할 때(D-09) 로그인 없이 열려 있어도 되는가 |
