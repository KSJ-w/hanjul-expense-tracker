# CLAUDE.md 작성 가이드 (CLAUDE_guide)

> `CLAUDE.md`는 AI 에이전트가 매 세션 자동으로 읽는 프로젝트 지도다. 요구 문서
> 층이 아니라 **컨텍스트 층**에 속하며, 진실의 원천은 합의가 아니라 **코드**다.
> 공통 규칙은 [README.md](README.md)를 따르되, 아래 두 가지는 적용하지 않는다.
>
> - README §2 ID 규율 — 이 파일에는 요구 번호가 흐르지 않는다
> - README §3 변경 이력·미결 사항 표 — 이력은 git이 소유한다

## 1. 입력과 출력

- **입력**: 실제 코드베이스의 구조·설정·실행 방법, 그리고 팀이 반복해 온 결정
- **출력**: `.claude/CLAUDE.md` — 세션마다 자동 로드되는 프로젝트 지도
- **진실의 원천**: 코드. 코드가 바뀌면 **같은 커밋에서** 이 파일도 바뀐다
- **경계**: 요구 문서가 아니다. FR·TC 번호를 여기서 확정하지 않고, 요구·시험의
  권위는 `docs/`의 요구 문서에 있음을 헤더에 명시한다
- **강제 장치가 아니다**: 이 파일은 시스템 프롬프트가 아니라 세션 시작 시
  전달되는 **컨텍스트**다. 준수 확률을 높일 뿐 보장하지 않는다. 반드시 막아야
  하는 동작은 hook이나 권한 설정으로 강제하고, 이 파일에는 판단 근거를 둔다
- **놓을 위치**: 팀이 공유할 것은 `./CLAUDE.md` 또는 `./.claude/CLAUDE.md`.
  개인 설정은 `CLAUDE.local.md`(gitignore), 모든 프로젝트 공통은
  `~/.claude/CLAUDE.md`. 상위 디렉토리의 파일까지 함께 로드된다

## 2. 작성 전 준비 (필수)

1. **코드베이스를 실제로 훑는다** — 진입점·설정 파일·디렉토리 구조·실행
   스크립트·테스트 실행 방법을 직접 열어 확인한다. 코드를 읽지 않고 쓴
   CLAUDE.md는 추측이며, **틀린 컨텍스트는 없는 것보다 나쁘다.**
   `/init`으로 초안을 만든 뒤 **코드에서 유도할 수 없는 것만 남기는 방향**으로
   다듬는 것이 빠르다.
2. **아키텍처 원칙(불변식)을 먼저 정한다** — 나머지 절보다 이것을 먼저 쓴다.
   에이전트가 구조를 훼손하는 것을 막는 유일한 방어선이다.
3. **리뷰에서 반복 지적한 것을 모은다** — 코딩 규칙의 재료다. 한 번도 지적된 적
   없는 일반론은 넣지 않는다.
4. **되돌려지면 안 되는 결정을 모은다** — 정책 로그의 재료다. 기각한 대안과
   근거 문서를 함께 확보한다.
5. **분량 감각** — 200줄 안팎을 목표로 한다. 파일이 길수록 지시 준수도가
   떨어진다. 길어지면 아래 기준으로 덜어 낸다.

| 내용 | 두는 곳 | 로드 시점 |
|---|---|---|
| 매 세션 항상 참인 것 | `CLAUDE.md` | 항상 |
| 특정 경로·파일 유형에만 해당하는 규칙 | `.claude/rules/*.md`(`paths:` 지정) | 그 파일을 다룰 때 |
| 여러 단계로 이뤄진 작업 절차 | `.claude/skills/<이름>/SKILL.md` | 관련 작업일 때 |

## 3. 문서 골격

```
# CLAUDE.md — <프로젝트명>
> 경계 선언 — 이 파일이 무엇이고 무엇이 아닌지.
>   "지원 지침이며 요구·시험의 권위는 docs/의 요구 문서에 있다"

## 1. 프로젝트 개요        한 문단(무엇을·누구를 위해) + 기술 스택 불릿
## 2. 아키텍처 원칙        어떤 변경에서도 깨지면 안 되는 구조 규칙을 번호
                          목록으로(보통 3~5개). **절 제목에 "최우선 준수"를
                          적어** 다른 규칙과 충돌할 때 이것을 먼저 지키게 한다.
                          예: `## 아키텍처 원칙 (Invariants — 최우선 준수)`
                          표시는 준수 확률을 높일 뿐 강제하지 않는다
## 3. 디렉토리 구조        주석 달린 트리 — 파일마다 역할·함정을 한 줄로
                          핵심 파일만. 전체 파일 목록이 아니다
## 4. API·계약 표면        표: | 메서드 | 경로 | 한 줄 설명 |
                          목록이지 명세가 아니다. 상세는 자동 생성 문서로
## 5. 개발 명령어          복붙 가능한 셸 블록. 순서가 중요하면 이유를 한 줄로
## 6. 정책·결정 로그       이 파일에서 가치가 가장 높은 절
                          | 정책 | 동작 | 이유 | 기각한 대안 | 근거 |
## 7. 코딩 규칙            언어·레이어별. 부정 규칙("~하지 않는다")을 포함
## 8. 보안 규칙            커밋 금지 대상, 비밀 관리 위치
## 9. 스킬 인덱스          표: | 스킬 | 언제 로드되나 |  (스킬이 있을 때만)
## 10. 문서-코드 동기화    표: | 코드 변경 | 같은 커밋에 갱신할 대상 |
                          체인의 강제 지점이다
```

절 순서에서 **아키텍처 원칙을 앞에 둔다.** 에이전트가 위에서부터 읽으므로,
구조를 깨뜨리지 않을 조건이 먼저 눈에 들어와야 한다.

## 4. 작성 규칙

- **남길지 뺄지는 한 문장으로 판정한다.** "이 문장을 지우면 미래의 작업자가
  잘못된 선택을 하는가?" 아니라면 뺀다. 규칙을 많이 쓰는 것이 아니라 **정확한
  것만** 남기는 것이 이 파일의 목표다.
- **코드를 복사하지 않는다.** 함수 본문·설정값 나열을 옮기면 코드가 바뀌는 순간
  거짓이 된다. 이 파일은 코드의 위치와 주의 지점을 가리키는 안내다.
- **코드를 읽어도 알 수 없는 것을 적는다.** 파일 이름을 반복하지 말고, 그 파일이
  왜 존재하는지·무엇을 조심해야 하는지를 적는다.
- **수치는 근거와 함께.** "성능 개선"이 아니라 "38ms→8ms(실측, `docs/report/...`)".
  숫자에 근거가 붙어 있으면 에이전트가 근거 없는 주장을 하지 못한다.
- **기각한 대안을 함께 적는다.** 되돌려지면 안 되는 결정에는 "무엇을 왜 안 했는지"가
  반드시 붙어야 한다. 이것이 없으면 다른 에이전트가 의도된 동작을 결함으로 오인해
  되돌린다. 단 **정책 표의 「기각한 대안」 칸 안에만 둔다** — 본문 서술로 풀어
  쓰면 에이전트가 현재 선택지로 오인한다.
- **예외는 날짜·승인과 함께 적고 확장을 금지한다.** "예외 2건(YYYY-MM-DD 승인).
  이 둘 외 신규 예외 추가 금지"처럼 쓴다.
- **원칙에 우선순위를 표시한다.** 에이전트는 요청을 해결하려고 구조를 우회한다
  (예: "검색이 느리니 검색할 때 다시 분석하자"). 절 제목의 "최우선 준수"는
  그런 제안을 스스로 기각할 확률을 높이는 표시이지 **차단 장치가 아니다.**
  절대 허용하면 안 되는 동작은 hook·권한 설정으로 막는다.
- **부정 규칙을 아끼지 않는다.** 명시된 금지가 없으면 에이전트는 가장 흔한 관행을
  선택하며, 그것이 이 팀의 관행이 아닐 수 있다.
- **서로 모순되는 규칙을 남기지 않는다.** 두 규칙이 충돌하면 에이전트는 임의로
  하나를 고른다. 상위 디렉토리의 `CLAUDE.md`·`.claude/rules/`까지 함께 본다.
- **틀린 컨텍스트는 없는 것보다 나쁘다.** 확신이 없는 서술은 지우고, 확인이 필요한
  것은 남기지 않는다.

### 문장 예시

| 절 | ✗ 부적합한 문장 | ✓ CLAUDE.md의 문장 |
|---|---|---|
| §3 디렉토리 | `search.py  # 검색` | `search.py  # 키워드 부분일치 검색. 정렬 로직은 rank.py 소유` |
| §6 정책 | 결과가 없으면 빈 목록을 반환한다 | 조회 0건과 조회 실패를 다른 응답으로 구분한다. 화면이 "장서 없음"으로 단정하지 않아야 하기 때문(`FR-LIB-02`). 둘 다 빈 목록으로 반환하는 안은 호출부가 구별할 수 없어 기각 |
| §7 코딩 규칙 | 설정을 잘 관리한다 | 임계값·경로를 코드에 직접 쓰지 않는다. 전부 `config.py` |

✗ 항목은 각각 **파일명 반복 · 이유 없는 서술 · 판정 불가능한 규칙**에 해당한다.

### 정책 로그 표 예시

| 정책 | 동작 | 이유 | 기각한 대안 | 근거 |
|---|---|---|---|---|
| 0건과 실패의 구분 | 0건은 `200` + 빈 목록, 실패는 `503` | 화면이 장서 부재를 단정하지 않으려면 두 경우를 구별해야 한다 | 둘 다 빈 목록 반환 — 호출부가 구분 불가 | `ADR-002` |

## 5. 금지 사항

- 함수 본문·설정값 나열 등 코드 복제
- 검증하지 못한 성능 주장, 근거 없는 수치
- FR·TC 번호의 확정 — 요구의 권위는 요구 문서에 있고, 여기서는 가리키기만 한다
- 전체 파일 목록을 옮긴 디렉토리 트리, 명세 수준의 API 표 — **코드를 읽으면
  알 수 있는 것**(레이아웃·의존성 목록·구조 개요)은 덜어 내고 함정과 근거를 남긴다
- 팀의 가치·철학 서술 — 읽기 좋지만 에이전트가 실행할 수 없다
- 폐기된 접근의 서술식 기록 — 에이전트가 현재 선택지로 오인한다
  (기각 이력은 정책 표의 칸 안에만)
- 이 파일 자체에 대한 규칙(메타 절), 여러 절에 흩어진 같은 규칙의 중복
- 매일 바뀌는 정보(진행 상황·현재 작업)
- 다른 도구용 미러 파일을 손으로 복사하는 것 — `AGENTS.md`가 이미 있으면
  `CLAUDE.md`에서 `@AGENTS.md`로 import하거나 심볼릭 링크로 잇는다

## 6. 완료 체크리스트

괄호의 판별 방법으로 **실제로 검사**한다.

- [ ] 아키텍처 원칙의 각 항목이 "어떤 변경에서도 깨지면 안 되는 규칙"이다
      (구현 방법이나 코딩 취향이 섞인 항목이 0개인지 확인)
- [ ] 아키텍처 원칙 절 제목에 "최우선 준수"가 표시돼 있다
- [ ] 디렉토리 트리의 모든 항목에 역할 주석이 있다
      (주석이 파일명을 반복하기만 하는 행이 0개인지 확인)
- [ ] 정책 로그의 각 항목에 **이유**가 있고, 되돌리면 안 되는 결정에는
      **기각한 대안**이 함께 있다 (이유 칸이 빈 행 0개)
- [ ] 모든 수치에 근거(측정 기록 또는 문서 경로)가 붙어 있다
- [ ] 코딩 규칙에 부정 규칙이 최소 하나 있다
- [ ] 코드 본문 복사가 없다
      (코드 블록을 열어 함수 본문·조건문이 있으면 삭제. 남길 수 있는 것은
      실행 명령과 디렉토리 트리뿐)
- [ ] 서로 모순되는 규칙이 없다
      (같은 주제를 다루는 항목을 모아 비교. 상위 디렉토리의 `CLAUDE.md`·
      `.claude/rules/`도 함께 확인)
- [ ] 코드를 읽으면 알 수 있는 서술이 남아 있지 않다
      (각 문장에 "이 문장을 지우면 잘못된 선택을 하는가?"를 적용)
- [ ] 문서-코드 동기화 표가 있고, 실제로 자주 바뀌는 것이 행으로 들어 있다
- [ ] 파일 안의 모든 경로·명령어·API가 현재 코드와 일치한다
      (경로를 하나씩 열어 존재를 확인)
      → 센 결과를 커밋 메시지의 검증 줄에 남긴다: `경로 __개 확인 / 불일치 __개`
- [ ] 분량이 200줄 안팎이다 (크게 넘으면 영역 지식을 SKILL.md로 분리)
