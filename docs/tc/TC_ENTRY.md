## 1. 시험 전략

- **수준** — 도메인·저장소·해석 경계에 대한 단위/통합 시험. 화면 조작은 이 문서의 자동화 대상이 아니다.
- **자동화 범위** — SRS 에서 검증 유형이 **시험**인 요구. 각 TC 는 하나의 실패 원인만 확인한다.
- **자동화 밖** — `NFR-ENTRY-04`(검사) · `NFR-ENTRY-05`(검사) · `NFR-ENTRY-06`(시연).
  SRS 가 적어 둔 이유를 그대로 옮긴다: 교체는 반복 실행할 수 없는 설계 변경 행위이고,
  보관되지 않았음의 증명은 저장 구성 전체의 검토로만 완결되며, 첫 기록 도달은 사람의 이해 과정을 봐야 한다.
- **합격값이 미승인인 요구** — `NFR-ENTRY-01`·`NFR-ENTRY-02` 는 측정 절차까지만 정의하고
  Pass/Fail 기준에 `합격값 승인 후 확정`이라고 적는다. TC 가 수치를 새로 만들지 않는다.

## 2. 환경과 전제

| 구분 | 전제 |

| 저장소 | 시험마다 새 임시 SQLite 파일. 시험 사이에 상태가 넘어가지 않는다 |
| 분류 집합 | 기본 제공 분류가 들어간 초기 상태(FR-CAT-04) |
| 기준일 | 별도 언급이 없으면 `2026-09-08`(화) |
| 해석 수단 | 기기 안 규칙 기반 수단. 외부 키를 쓰지 않는다 |
| 네트워크 | 시험 중 나가는 요청을 가로채 센다(SRS S-05 결정 ②) |

## 4. 실행 순서

그룹 간 의존은 없다. 각 TC 는 자기 전제를 스스로 만든다.
다만 TC-ENTRY-36 은 소스 전체를 읽으므로 다른 시험과 같은 실행 안에서 돌아야
드리프트를 같은 시점에 잡는다.

## 5. 판정 규칙

실행 결과는 `PASS` · `FAIL` · `SKIPPED` · `BLOCKED`(전제 미충족) · `NOT_RUN` 다섯 중 하나로 적는다.
**`PASS` 가 아닌 것은 전부 통과가 아니다.**

1. 스킵은 통과가 아니다.
2. 실행하지 않은 시험은 통과가 아니다.
3. 정적 검사·대역 시험은 실제 실행 환경 검증을 대체하지 않는다.
4. 테스트 삭제·skip 처리·assertion 완화로 실패를 숨기지 않는다.
5. 같은 요구를 여러 테스트가 검증해도 통과 개수로 충족을 부풀리지 않는다.
6. 문서에 없는 TC 태그(orphan)는 오타 또는 드리프트다 — 커밋 전 0 이어야 한다.
7. 테스트 없는 TC(미커버)는 실패가 아니라 "자동화 미연결"이며, 수동·시연 유형인지 미구현인지 구분해 표시한다.
