## 1. 문서 목적과 경계

이 문서는 아래 질문에 답한다.

- 이 제품을 쓰는 사람은 누구이고 무엇을 하려 하는가
- 기록을 남기고 되짚어 보는 과정이 처음부터 끝까지 어떻게 이어지는가
- 각 과업이 "되었다"고 말할 수 있는 조건은 무엇인가

이 문서가 두지 않는 것:

| 두지 않는 것 | 소유 문서 |
|---|---|
| 요구의 정의와 우선순위 | RFP |
| 비범위 | RFP §3.2 (이 문서는 인용만 한다) |
| 검증 가능한 시스템 요구, 수치 합격선 | SRS |
| 시험 절차와 시험 자료 | TC |
| 구조·데이터·기술 선택 | SDD |

## 2. 사용자 역할

### 2.1 직접 사용자

| 역할 | 목표 | 수행 책임 |
|---|---|---|
| 가계부 작성자 | 그날의 지출·수입을 부담 없이 남기고, 쌓인 기록으로 자신의 소비를 되짚어 본다 | 기록의 확정, 분류 체계의 유지, 예산의 설정, 기록의 반출 |

이 제품의 소프트웨어 역할은 위 하나뿐이다. 역할 사이의 권한 구분은 이번 범위가
아니다(RFP §3.2).

### 2.2 외부 이해관계자

**제품의 역할이 아니다.** 제품에 접근하지 않으며 과업을 수행하지 않는다.

| 이해관계자 | 관계 |
|---|---|
| 외부 해석 수단 제공자 | 입력의 해석을 맡는 위치. 제품을 사용하지 않는다 |
| 개인정보·금융 감독기관 | 처리 기준과 진입 조건을 정한다. 제품을 사용하지 않는다 |

### 2.3 역할별 접근

| 과업 | 가계부 작성자 | 외부 이해관계자 |
|---|---|---|
| 기록의 생성·확정 | 허용 | 불가(제품 역할 아님) |
| 기록의 수정·삭제·되살리기 | 허용 | 불가 |
| 분류의 추가·변경·삭제 | 허용 | 불가 |
| 기록의 조회·요약·검색 | 허용 | 불가 |
| 예산의 설정 | 허용 | 불가 |
| 기록의 반출·반입 | 허용 | 불가 |

## 3. 보존할 제품 원칙과 범위

**원칙** (RFP §2 계승)

1. 기록의 마찰을 가장 먼저 줄인다.
2. 자동 해석은 제안이지 확정이 아니다.
3. 자동이 실패해도 길이 끊기지 않는다.
4. 분류는 사용자의 것이다.
5. 처음 열었을 때 무엇을 하는 도구인지 알 수 있어야 한다.
6. 밖으로 나가는 것은 최소한으로 한다.
7. 기록은 사용자의 손에 남는다.

**비범위** — RFP §3.2가 소유한다. 이 문서는 새 비범위를 만들지 않으며, 아래는
인용이다: 자연어를 통한 조회·수정·삭제·설정 변경 / 금융기관 자동 연동 / 여러
사용자·로그인·공유 / 모바일 전용 애플리케이션 / 외화·다국어 / 투자·자산 관리 /
계좌·결제수단별 잔액 추적 / 세무 신고용 자료 / 학습 모델 자체 개발 / 외부
백업·동기화 서비스.

## 4. end-to-end 사용자 여정

### 4.1 정상 흐름 — 가계부 작성자

1. 제품에 접근한다. 기록을 남기는 수단이 안내 없이 눈앞에 있다.
2. 오늘 쓴 돈을 자기 말로 한 줄 적는다. 또는 영수증 이미지를 준다. 또는 자동
   해석을 쓰지 않고 직접 항목을 채운다.
3. 시스템이 해석해 날짜·금액·분류·수입/지출 구분이 채워진 기록 후보를 보여 준다.
4. 내용을 훑어보고, 틀린 항목이 있으면 고친다. 분류가 마음에 안 들면 자기 분류
   중에서 다시 고른다.
5. 확인한다. 이때 비로소 기록이 된다.
6. 며칠 뒤 달력을 열어 그날그날의 기록을 확인한다.
7. 이번 달의 수입·지출 합계와 분류별 구성을 본다. 예산을 정해 두었으면 얼마나
   남았는지 함께 본다.
8. 필요하면 조건을 걸어 지난 기록을 찾고, 기록 전체를 파일로 내보내 둔다.

### 4.2 권한·실패·복구 여정

| 상황 | 제품이 보여줄 의미 | 사용자의 다음 행동 |
|---|---|---|
| 적은 문장을 해석하지 못했다 | 해석하지 못했다는 사실. 기록이 실패한 것은 아니다 | 채워진 만큼을 받아 직접 마저 채운다 |
| 일부 항목만 해석됐다 | 어떤 항목이 비어 있는지 | 비어 있는 항목만 채워 확인한다 |
| 외부 해석 수단이 응답하지 않는다 | 지금 자동 해석을 쓸 수 없다는 사실 | 직접 입력으로 기록을 남긴다 |
| 이미지에서 읽어 낸 것이 없다 | 이미지에서 읽지 못했다는 사실. 이미지가 잘못됐다고 단정하지 않는다 | 직접 입력으로 넘어가거나 다른 이미지를 준다 |
| 조건에 맞는 기록이 없다 | 조건에 맞는 기록을 찾지 못했다는 사실 | 조건을 바꿔 다시 찾는다 |
| 기록이 남아 있는 분류를 지우려 한다 | 그 분류에 기록이 남아 있다는 사실 | 확인하고 진행하거나 그만둔다 |
| 기록을 잘못 지웠다 | 지운 기록을 되살릴 수 있다는 사실 | 되살린다 |
| 권한이 부족하다 | **이 제품에는 해당하지 않는다** — 역할이 하나뿐이라 권한으로 막히는 상황이 없다 | — |

## 5. 에픽과 사용자 스토리

**우선순위 대응** — RFP의 `M`↔`P0`, `S`↔`P1`, `C`↔`P2`. 스토리의 우선순위는 그
스토리가 **새로 파생하는 요구**의 우선순위를 따른다. 이미 상위 스토리에서 파생된
`M` 요구를 하위 스토리의 수용 조건이 다시 인용하는 것은 어긋남이 아니다 — 그
요구는 이미 P0 스토리에서 보장되기 때문이다.

### EPIC-01 — 한 줄로 기록 남기기

#### US-01-01 — 자기 말로 적어 기록 남기기 (P0)

> **As** 가계부 작성자로서 **I want** 오늘 쓴 돈을 자기 말로 한 줄 적는 것만으로
> 기록하고 **So that** 항목을 나눠 채우느라 기록을 미루지 않게 된다

- 사용자: 가계부 작성자 · 연계 RFP: FR-ENTRY-01, FR-ENTRY-02, FR-ENTRY-05,
  FR-ENTRY-06, NFR-ENTRY-01

**수용 조건**

1. **Given** 금액과 쓴 곳이 담긴 한 줄을 적었을 때 **When** 입력을 제출하면
   **Then** 날짜·금액·분류·수입인지 지출인지가 채워진 기록 후보가 제시되어야 한다
   (FR-ENTRY-01)
2. **Given** 문장에 "어제"·"지난주 금요일" 같은 상대적 날짜 표현이 있을 때
   **When** 입력을 제출하면 **Then** 그 표현이 확정된 날짜로 바뀌어 후보에 반영되어야
   한다 (FR-ENTRY-02)
3. **Given** 기록 후보가 제시되었을 때 **When** 사용자가 확인하지 않고 그대로 두면
   **Then** 그 후보는 확정된 기록으로 저장되어서는 안 된다 (FR-ENTRY-05)
4. **Given** 기록 후보의 어떤 항목이 잘못 채워졌을 때 **When** 확인 전에 그 항목을
   고치면 **Then** 고친 값이 확정될 내용에 반영되어야 한다 (FR-ENTRY-06)
5. **Given** 해석에 필요한 항목을 채우지 못했을 때 **When** 입력을 제출하면
   **Then** 채운 항목과 채우지 못한 항목이 구분되어 제시되어야 하며, 입력이 사라져서는
   안 된다 (FR-ENTRY-01, FR-ENTRY-05)
6. **Given** 사용자가 입력을 제출했을 때 **When** 후보가 만들어지는 동안이면
   **Then** 진행 중임이 사용자에게 전달되고, 후보 제시까지의 시간이 SRS §3이 정한
   범위 안이어야 한다 (NFR-ENTRY-01)

#### US-01-02 — 한 번에 여러 건 적기 (P1)

> **As** 가계부 작성자로서 **I want** 하루에 있었던 여러 건을 한 번에 적고
> **So that** 건마다 입력을 반복하지 않아도 된다

- 사용자: 가계부 작성자 · 연계 RFP: FR-ENTRY-03

**수용 조건**

1. **Given** 한 줄에 둘 이상의 거래가 담겼을 때 **When** 입력을 제출하면
   **Then** 각 거래가 별개의 기록 후보로 제시되어야 한다 (FR-ENTRY-03)
2. **Given** 여러 후보 중 일부만 해석되었을 때 **When** 후보가 제시되면
   **Then** 해석된 것과 해석되지 않은 것이 구분되어야 하며, 해석되지 않은 부분 때문에
   해석된 후보가 사라져서는 안 된다 (FR-ENTRY-03)
3. **Given** 여러 후보가 제시되었을 때 **When** 그중 일부만 확인하면
   **Then** 확인한 후보만 기록이 되어야 한다 (FR-ENTRY-05)

#### US-01-03 — 열자마자 기록 시작하기 (P0)

> **As** 가계부 작성자로서 **I want** 제품을 열었을 때 기록을 남기는 자리가 바로
> 보이길 **So that** 무엇부터 해야 할지 찾는 데 시간을 쓰지 않는다

- 사용자: 가계부 작성자 · 연계 RFP: FR-ENTRY-17

**수용 조건**

1. **Given** 제품에 처음 접근했을 때 **When** 첫 진입 지점이 열리면
   **Then** 기록을 남기는 수단이 별도의 안내를 거치지 않고 제시되어야 한다 (FR-ENTRY-17)
2. **Given** 아직 기록이 하나도 없을 때 **When** 첫 진입 지점이 열리면
   **Then** 기록이 없다는 사실이 제품을 쓸 수 없다는 뜻으로 표시되어서는 안 된다
   (FR-ENTRY-17)

#### US-01-04 — 배우지 않고 첫 기록에 도달하기 (P1)

> **As** 이 제품을 처음 접한 사람으로서 **I want** 설명을 읽지 않고 첫 기록을 남기고
> **So that** 도구를 익히는 일 자체가 기록의 걸림돌이 되지 않는다

- 사용자: 가계부 작성자 · 연계 RFP: NFR-ENTRY-06

**수용 조건**

1. **Given** 제품을 처음 접한 사람일 때 **When** 첫 기록을 남기려 하면
   **Then** 별도의 안내 없이 첫 기록에 도달할 수 있어야 한다 (NFR-ENTRY-06)
2. **Given** 처음 접한 사람이 무엇을 적어야 할지 모를 때 **When** 입력 자리를 보면
   **Then** 무엇을 적으면 되는지가 예시로 드러나야 하며, 별도의 학습 과정을 요구해서는
   안 된다 (NFR-ENTRY-06)

### EPIC-02 — 이미지로 기록 남기기

#### US-02-01 — 영수증 이미지로 기록 남기기 (P0)

> **As** 가계부 작성자로서 **I want** 영수증이나 결제 내역 이미지를 주는 것만으로
> 기록하고 **So that** 영수증을 보며 옮겨 적는 일을 하지 않아도 된다

- 사용자: 가계부 작성자 · 연계 RFP: FR-ENTRY-04, FR-ENTRY-05, FR-ENTRY-06, FR-ENTRY-18

**수용 조건**

1. **Given** 금액과 상호가 담긴 이미지를 주었을 때 **When** 해석을 요청하면
   **Then** 날짜·금액·분류·수입인지 지출인지가 채워진 기록 후보가 제시되어야 한다
   (FR-ENTRY-04)
2. **Given** 이미지에서 아무 항목도 읽어 내지 못했을 때 **When** 후보가 제시되면
   **Then** 읽어 내지 못했다는 사실이 전달되어야 하며, 그 이미지에 기록할 내용이 없다는
   뜻으로 표시되어서는 안 된다 (FR-ENTRY-04)
3. **Given** 이미지에서 일부 항목만 읽어 냈을 때 **When** 후보가 제시되면
   **Then** 비어 있는 항목을 사용자가 채워 확인할 수 있어야 한다 (FR-ENTRY-06)
4. **Given** 이미지로부터 후보가 만들어졌을 때 **When** 사용자가 확인하지 않으면
   **Then** 그 후보는 확정된 기록으로 저장되어서는 안 된다 (FR-ENTRY-05)
5. **Given** 이미지를 첨부하려 할 때 **When** 첨부 동작을 하면
   **Then** 그 이미지가 외부로 전송된다는 사실과 민감한 부분을 가릴 수 있다는 안내가
   해석 요청 전에 제시되어야 한다 (FR-ENTRY-18)

#### US-02-02 — 근거가 된 이미지 다시 보기 (P1)

> **As** 가계부 작성자로서 **I want** 어떤 기록의 출처가 된 이미지를 나중에 다시 보고
> **So that** 금액이 맞는지 나중에도 스스로 확인할 수 있다

- 사용자: 가계부 작성자 · 연계 RFP: FR-ENTRY-13

**수용 조건**

1. **Given** 이미지로부터 만들어진 기록이 있을 때 **When** 그 기록을 열면
   **Then** 근거가 된 이미지를 다시 확인할 수 있어야 한다 (FR-ENTRY-13)
2. **Given** 이미지 없이 만들어진 기록일 때 **When** 그 기록을 열면
   **Then** 근거 이미지가 없다는 사실이 기록이 잘못되었다는 뜻으로 표시되어서는 안 된다
   (FR-ENTRY-13)

### EPIC-03 — 손으로 기록하고 바로잡기

#### US-03-01 — 자동 해석 없이 직접 기록하기 (P0)

> **As** 가계부 작성자로서 **I want** 자동 해석을 거치지 않고 직접 항목을 채워
> 기록하고 **So that** 해석이 틀리거나 되지 않을 때도 기록이 끊기지 않는다

- 사용자: 가계부 작성자 · 연계 RFP: FR-ENTRY-07, FR-ENTRY-08

**수용 조건**

1. **Given** 자동 해석을 쓰지 않으려 할 때 **When** 직접 입력을 선택하면
   **Then** 날짜·금액·분류·수입/지출 구분을 사람이 채워 기록을 만들 수 있어야 한다
   (FR-ENTRY-08)
2. **Given** 해석이 실패했거나 일부 항목만 채워졌을 때 **When** 사용자가 이어받으면
   **Then** 이미 채워진 항목이 남은 채로 나머지를 채워 기록을 완성할 수 있어야 한다
   (FR-ENTRY-07)
3. **Given** 필수 항목을 채우지 않았을 때 **When** 확인하려 하면
   **Then** 어떤 항목이 비어 있는지 전달되어야 하며, 이미 채운 내용이 사라져서는 안 된다
   (FR-ENTRY-08)

#### US-03-02 — 확정된 기록 고치고 지우기 (P0)

> **As** 가계부 작성자로서 **I want** 이미 남긴 기록을 나중에 고치거나 지우고
> **So that** 잘못 남은 기록이 쌓여 되짚어 보는 일을 망치지 않게 한다

- 사용자: 가계부 작성자 · 연계 RFP: FR-ENTRY-09, FR-ENTRY-10

**수용 조건**

1. **Given** 확정된 기록이 있을 때 **When** 항목을 고치면 **Then** 고친 내용이 이후의
   조회와 요약에 반영되어야 한다 (FR-ENTRY-09)
2. **Given** 확정된 기록이 있을 때 **When** 그 기록을 지우면 **Then** 이후의 조회와
   요약에서 빠져야 한다 (FR-ENTRY-10)
3. **Given** 기록을 지우려 할 때 **When** 지우는 동작을 시작하면
   **Then** 지운 뒤 되살릴 수 있다는 사실이 전달되어야 한다 (FR-ENTRY-10)
4. **Given** 기록을 고치다가 필요한 항목을 비웠을 때 **When** 고친 내용을 확정하려 하면
   **Then** 어떤 항목이 비었는지 전달되어야 하며 원래 기록이 훼손되어서는 안 된다
   (FR-ENTRY-09)

#### US-03-03 — 잘못 지운 기록 되살리기 (P1)

> **As** 가계부 작성자로서 **I want** 잘못 지운 기록을 되살리고 **So that** 실수로
> 기록을 영영 잃지 않는다

- 사용자: 가계부 작성자 · 연계 RFP: FR-ENTRY-11

**수용 조건**

1. **Given** 방금 기록을 지웠을 때 **When** 되살리기를 선택하면 **Then** 지우기 전의
   내용 그대로 기록이 돌아와야 한다 (FR-ENTRY-11)
2. **Given** 되살릴 수 있는 기록이 없을 때 **When** 되살리기를 시도하면
   **Then** 되살릴 대상이 없다는 사실이 전달되어야 하며, 다른 기록이 바뀌어서는 안 된다
   (FR-ENTRY-11)

#### US-03-04 — 자동 해석을 쓸 수 없을 때도 기록하기 (P0)

> **As** 가계부 작성자로서 **I want** 자동 해석이 동작하지 않는 상황에서도 기록을
> 남기고 **So that** 남의 사정 때문에 내 기록이 끊기지 않는다

- 사용자: 가계부 작성자 · 연계 RFP: FR-ENTRY-14, NFR-ENTRY-03

**수용 조건**

1. **Given** 외부 해석 수단이 응답하지 않을 때 **When** 기록을 남기려 하면
   **Then** 직접 입력으로 기록을 만드는 경로가 막히지 않아야 한다 (FR-ENTRY-14)
2. **Given** 외부 해석 수단이 응답하지 않을 때 **When** 자동 해석을 요청하면
   **Then** 지금 자동 해석을 쓸 수 없다는 사실이 사용자에게 전달되어야 한다
   (NFR-ENTRY-03)
3. **Given** 자동 해석이 실패했을 때 **When** 실패가 전달되면 **Then** 사용자가 적은
   입력 내용이 사라져서는 안 된다 (FR-ENTRY-14)

### EPIC-04 — 반복되는 것 처리하기

   (FR-ENTRY-12)

### EPIC-05 — 내 기준의 분류 유지하기

#### US-05-01 — 분류를 내 손으로 만들고 고치고 지우기 (P0)

> **As** 가계부 작성자로서 **I want** 분류를 내가 만들고 이름을 바꾸고 지우고
> **So that** 남이 정한 분류에 내 소비를 끼워 맞추지 않아도 된다

- 사용자: 가계부 작성자 · 연계 RFP: FR-CAT-01, FR-CAT-02, FR-CAT-03, FR-CAT-08,
  NFR-CAT-01

**수용 조건**

1. **Given** 새 분류가 필요할 때 **When** 분류를 추가하면 **Then** 이후의 기록에서 그
   분류를 고를 수 있어야 한다 (FR-CAT-01)
2. **Given** 분류의 이름이 마음에 들지 않을 때 **When** 이름을 바꾸면 **Then** 그
   분류에 속한 기존 기록이 바뀐 이름 아래 그대로 남아 있어야 한다 (FR-CAT-02,
   NFR-CAT-01)
3. **Given** 기록이 남아 있는 분류일 때 **When** 그 분류를 지우려 하면
   **Then** 기록이 남아 있다는 사실을 확인받기 전에 지워져서는 안 된다 (FR-CAT-08)
4. **Given** 기록이 없는 분류일 때 **When** 그 분류를 지우면 **Then** 이후의 기록에서
   그 분류가 선택지로 나타나지 않아야 한다 (FR-CAT-03)
5. **Given** 분류를 지운 뒤일 때 **When** 지난 기록을 조회하면 **Then** 그 기록이 어느
   분류에 속했는지가 사라져서는 안 된다 (NFR-CAT-01)

#### US-05-02 — 시작할 때부터 쓸 분류가 있기 (P0)

> **As** 처음 시작하는 가계부 작성자로서 **I want** 처음부터 쓸 만한 분류가 준비되어
> 있길 **So that** 분류를 설계하는 일부터 시작하지 않아도 된다

- 사용자: 가계부 작성자 · 연계 RFP: FR-CAT-04

**수용 조건**

1. **Given** 아무 분류도 만들지 않은 상태일 때 **When** 첫 기록을 남기려 하면
   **Then** 바로 고를 수 있는 분류가 이미 있어야 한다 (FR-CAT-04)
2. **Given** 미리 제공된 분류가 마음에 들지 않을 때 **When** 그것을 바꾸거나 지우면
   **Then** 사용자의 변경이 유지되어야 하며 다시 되돌아와서는 안 된다 (FR-CAT-04,
   FR-CAT-02)

#### US-05-03 — 내 분류 안에서만 배정받기 (P0)

> **As** 가계부 작성자로서 **I want** 자동 해석이 내가 가진 분류 중에서만 고르길
> **So that** 모르는 분류가 늘어나 내 분류 체계가 흐트러지지 않는다

- 사용자: 가계부 작성자 · 연계 RFP: FR-CAT-06

**수용 조건**

1. **Given** 입력의 내용이 기존 분류 어디에도 잘 맞지 않을 때 **When** 자동 해석이
   분류를 배정하면 **Then** 사용자가 보유하지 않은 분류를 새로 만들어 배정해서는 안 된다
   (FR-CAT-06)
2. **Given** 마땅한 분류를 고르지 못했을 때 **When** 후보가 제시되면 **Then** 분류가
   정해지지 않았다는 사실이 드러나야 하며, 임의의 분류로 채워져서는 안 된다 (FR-CAT-06)

#### US-05-04 — 수입과 지출의 분류를 구분해 쓰기 (P1)

> **As** 가계부 작성자로서 **I want** 수입에 쓰는 분류와 지출에 쓰는 분류가 구분되길
> **So that** 고를 때 엉뚱한 분류가 섞여 나오지 않는다

- 사용자: 가계부 작성자 · 연계 RFP: FR-CAT-05

**수용 조건**

1. **Given** 지출을 기록할 때 **When** 분류를 고르면 **Then** 지출에 쓰는 분류가
   제시되어야 한다 (FR-CAT-05)
2. **Given** 수입을 기록할 때 **When** 분류를 고르면 **Then** 수입에 쓰는 분류가
   제시되어야 한다 (FR-CAT-05)
3. **Given** 수입·지출 구분이 아직 정해지지 않은 후보일 때 **When** 분류를 고르려 하면
   **Then** 구분이 정해지지 않았다는 사실이 드러나야 하며, 한쪽으로 단정되어서는 안 된다
   (FR-CAT-05, FR-CAT-06)

#### US-05-05 — 한번 고친 분류가 다음에 반영되기 (P1)

> **As** 가계부 작성자로서 **I want** 내가 고쳐 준 분류를 다음에도 기억하길
> **So that** 같은 곳을 쓸 때마다 같은 수정을 반복하지 않는다

- 사용자: 가계부 작성자 · 연계 RFP: FR-CAT-07

**수용 조건**

1. **Given** 확인 단계에서 자동 배정된 분류를 고쳤을 때 **When** 이후 같은 성격의
   입력을 하면 **Then** 고쳐 준 분류가 반영되어 제시되어야 한다 (FR-CAT-07)
2. **Given** 고쳐 준 분류가 반영되어 제시되었을 때 **When** 사용자가 다시 다른 분류로
   고치면 **Then** 마지막에 고친 것이 이후에 반영되어야 한다 (FR-CAT-07)
3. **Given** 반영된 분류가 이번 건에는 맞지 않을 때 **When** 확인 단계에서 다시 고르면
   **Then** 이번 건에 대해서는 사용자가 고른 것이 우선해야 한다 (FR-CAT-07, FR-ENTRY-06)

### EPIC-06 — 날짜로 되짚어 보기

#### US-06-01 — 달력에서 그날의 기록 보기 (P0)

> **As** 가계부 작성자로서 **I want** 달력에서 어느 날 무엇이 있었는지 보고
> **So that** 날짜를 기준으로 내 소비를 떠올릴 수 있다

- 사용자: 가계부 작성자 · 연계 RFP: FR-VIEW-01, FR-VIEW-02, FR-VIEW-12

**수용 조건**

1. **Given** 여러 날에 기록이 있을 때 **When** 달력을 열면 **Then** 어느 날에 기록이
   있는지가 날짜별로 드러나야 한다 (FR-VIEW-01)
2. **Given** 기록이 있는 날일 때 **When** 그 날짜를 고르면 **Then** 그날의 기록 목록이
   제시되어야 한다 (FR-VIEW-02)
3. **Given** 아직 아무 기록도 없을 때 **When** 달력을 열면 **Then** 기록이 없다는 사실이
   드러나야 하며 달력을 볼 수 없다고 표시되어서는 안 된다 (FR-VIEW-01)
4. **Given** 그 달에 일요일과 공휴일이 있을 때 **When** 달력을 열면 **Then** 그 날짜들이
   다른 날과 구별되어야 하며, 구별은 색 하나에만 기대서는 안 된다 (FR-VIEW-12)
5. **Given** 공휴일인 날짜일 때 **When** 달력을 보면 **Then** 그날이 무슨 날인지 이름으로
   알 수 있어야 한다 — 색을 보지 못해도 같은 뜻이 전달되어야 한다 (FR-VIEW-12)

#### US-06-02 — 찾지 못한 것과 없었던 것 구분하기 (P0)

> **As** 가계부 작성자로서 **I want** 기록이 없는 것과 지출이 없었던 것을 구분해서 보고
> **So that** 아직 안 적은 지출을 "안 썼다"고 착각하지 않는다

- 사용자: 가계부 작성자 · 연계 RFP: FR-VIEW-07

**수용 조건**

1. **Given** 고른 날짜에 기록이 하나도 없을 때 **When** 그 날짜를 조회하면
   **Then** 기록이 없다고 표시하되 그날 지출·수입이 없었다는 뜻으로 표시해서는 안 된다
   (FR-VIEW-07)
2. **Given** 조건에 맞는 기록이 없을 때 **When** 결과를 보면 **Then** 조건에 맞는 기록을
   찾지 못했다는 의미로 표시되어야 한다 (FR-VIEW-07)
3. **Given** 기간 요약의 값이 0일 때 **When** 요약을 보면 **Then** 그 기간에 거래가
   없었다고 단정하는 표현이 쓰여서는 안 된다 (FR-VIEW-07)

### EPIC-07 — 기간으로 돌아보기

#### US-07-01 — 이번 주·달·해의 수입과 지출 보기 (P0)

> **As** 가계부 작성자로서 **I want** 기간별로 얼마를 벌고 얼마를 썼는지 한눈에 보고
> **So that** 기록이 숫자를 세는 일로 끝나지 않고 판단으로 이어진다

- 사용자: 가계부 작성자 · 연계 RFP: FR-VIEW-03, FR-VIEW-04

**수용 조건**

   수입·지출 합계가 제시되어야 한다 (FR-VIEW-03)
2. **Given** 기간 안에 지출 기록이 있을 때 **When** 그 기간의 요약을 보면
   **Then** 지출이 분류별 구성으로 제시되어야 한다 (FR-VIEW-04)
3. **Given** 기간 안에 기록이 하나도 없을 때 **When** 요약을 보면 **Then** 합계가 비어
   있음이 드러나야 하며 요약을 볼 수 없다고 표시되어서는 안 된다 (FR-VIEW-03)

#### US-07-02 — 시간에 따른 변화 보기 (P1)

> **As** 가계부 작성자로서 **I want** 수입과 지출이 시간에 따라 어떻게 변했는지 보고
> **So that** 이번 달이 평소보다 많은지 적은지 알 수 있다

- 사용자: 가계부 작성자 · 연계 RFP: FR-VIEW-05

**수용 조건**

1. **Given** 여러 기간에 걸쳐 기록이 있을 때 **When** 변화를 보면 **Then** 수입·지출이
   시간 축에 따라 제시되어야 한다 (FR-VIEW-05)
2. **Given** 비교할 기간이 하나뿐일 때 **When** 변화를 보면 **Then** 비교할 기간이 부족함이
   드러나야 하며 변화가 없다고 단정해서는 안 된다 (FR-VIEW-05, FR-VIEW-07)

#### US-07-03 — 예산과 견주어 보기 (P1)

> **As** 가계부 작성자로서 **I want** 스스로 정한 한도와 실제 지출을 견주고
> **So that** 남은 기간에 얼마를 쓸 수 있는지 판단할 수 있다

- 사용자: 가계부 작성자 · 연계 RFP: FR-VIEW-08, FR-VIEW-09

**수용 조건**

1. **Given** 분류별 기간 예산을 정하려 할 때 **When** 예산을 입력하면 **Then** 그 분류와
   기간에 대한 예산이 남아야 한다 (FR-VIEW-08)
2. **Given** 예산이 정해진 분류에 지출이 있을 때 **When** 예산 대비를 보면 **Then** 정해진
   예산과 같은 기간의 실제 지출이 함께 제시되어야 한다 (FR-VIEW-09)
3. **Given** 예산을 정하지 않은 분류일 때 **When** 예산 대비를 보면 **Then** 예산이 없다는
   사실이 드러나야 하며 예산을 초과했다는 뜻으로 표시되어서는 안 된다 (FR-VIEW-09)

#### US-07-04 — 기록이 쌓여도 요약이 바로 보이기 (P1)

> **As** 오래 써 온 가계부 작성자로서 **I want** 기록이 많이 쌓인 뒤에도 요약이 바로
> 보이길 **So that** 돌아보는 일 자체가 부담이 되어 그만두지 않는다

- 사용자: 가계부 작성자 · 연계 RFP: NFR-VIEW-01

**수용 조건**

1. **Given** 기록이 누적된 상태일 때 **When** 기간 요약을 요청하면 **Then** 요약이
   제시되기까지의 시간이 SRS §3이 정한 범위 안이어야 한다 (NFR-VIEW-01)
2. **Given** 요약을 만드는 데 시간이 걸릴 때 **When** 사용자가 기다리는 동안이면
   **Then** 진행 중임이 전달되어야 하며 요약이 비어 있다고 표시되어서는 안 된다
   (NFR-VIEW-01, FR-VIEW-07)

### EPIC-08 — 찾고, 지켜 내기

#### US-08-01 — 조건을 걸어 지난 기록 찾기 (P1)

> **As** 가계부 작성자로서 **I want** 기간·분류·금액·적은 내용으로 지난 기록을 찾고
> **So that** 달력을 한 장씩 넘기지 않고도 그때 그 지출을 확인할 수 있다

- 사용자: 가계부 작성자 · 연계 RFP: FR-VIEW-06, FR-VIEW-13

**수용 조건**

1. **Given** 조건에 맞는 기록이 있을 때 **When** 조건을 걸어 찾으면 **Then** 조건에 맞는
   기록만 제시되어야 한다 (FR-VIEW-06)
2. **Given** 여러 조건을 함께 걸었을 때 **When** 찾으면 **Then** 모든 조건을 만족하는
   기록만 제시되어야 한다 (FR-VIEW-06)
3. **Given** 조건에 맞는 기록이 없을 때 **When** 찾으면 **Then** 찾지 못했다는 의미로
   제시되어야 하며 그런 지출이 없었다는 뜻으로 표시되어서는 안 된다 (FR-VIEW-07)
4. **Given** 찾고 싶은 것을 한 줄로 적었을 때 **When** 보내면 **Then** 그 문장이 조건으로
   바뀌어 조건에 맞는 기록이 제시되어야 한다 (FR-VIEW-13)
5. **Given** 문장이 조건으로 바뀌었을 때 **When** 결과를 보면 **Then** **어떤 조건으로
   찾았는지**를 함께 알 수 있어야 한다 — 찾지 못한 것과 잘못 알아들은 것은 다르고,
   그 둘을 사용자가 구별할 수 없으면 다시 적어 볼 수도 없다 (FR-VIEW-13)
6. **Given** 문장에서 조건을 하나도 알아듣지 못했을 때 **When** 보내면 **Then** 알아듣지
   못했다는 사실이 전달되어야 하며, 조건 없는 전체 목록을 결과인 것처럼 제시해서는
   안 된다 (FR-VIEW-13)

#### US-08-02 — 기록을 파일로 내보내 지켜 두기 (P1)

> **As** 가계부 작성자로서 **I want** 내 기록을 파일로 내보내 두고 **So that** 도구가
> 바뀌거나 멈춰도 지금까지의 기록을 잃지 않는다

- 사용자: 가계부 작성자 · 연계 RFP: FR-VIEW-10, NFR-VIEW-03

**수용 조건**

1. **Given** 기록이 쌓여 있을 때 **When** 반출을 요청하면 **Then** 기록이 담긴 파일을
   얻을 수 있어야 한다 (FR-VIEW-10)
2. **Given** 반출한 파일이 있을 때 **When** 기록이 비어 있는 상태에서 그 파일로 되살리면
   **Then** 반출 시점의 기록과 같아야 한다 (NFR-VIEW-03)
3. **Given** 반출할 기록이 하나도 없을 때 **When** 반출을 요청하면 **Then** 반출할 기록이
   없다는 사실이 전달되어야 하며 반출이 실패했다는 뜻으로 표시되어서는 안 된다
   (FR-VIEW-10, FR-VIEW-07)

#### US-08-03 — 내보낸 파일로 기록 들여오기 (P2)

> **As** 가계부 작성자로서 **I want** 내보낸 파일에서 기록을 다시 들여오고
> **So that** 기기를 옮기거나 처음부터 다시 시작해도 기록이 이어진다

- 사용자: 가계부 작성자 · 연계 RFP: FR-VIEW-11

**수용 조건**

1. **Given** 반출한 파일이 있을 때 **When** 반입하면 **Then** 파일에 담긴 기록이 조회와
   요약에 나타나야 한다 (FR-VIEW-11)
2. **Given** 파일의 형식이 맞지 않을 때 **When** 반입하면 **Then** 반입할 수 없다는 사실이
   전달되어야 하며 기존 기록이 훼손되어서는 안 된다 (FR-VIEW-11)
3. **Given** 반입하려는 기록이 이미 있는 기록과 겹칠 때 **When** 반입하면 **Then** 겹치는
   기록을 어떻게 처리했는지가 사용자에게 드러나야 한다 (FR-VIEW-11)

### EPIC-09 — 무엇이 밖으로 나가는지 알기

#### US-09-01 — 해석에 필요한 것만 나가게 하기 (P0)

> **As** 가계부 작성자로서 **I want** 내 기록과 이미지가 해석 말고 다른 이유로 밖에
> 나가지 않길 **So that** 내 소비 내역이 어디까지 갔는지 걱정하지 않아도 된다

- 사용자: 가계부 작성자 · 연계 RFP: FR-ENTRY-15

**수용 조건**

1. **Given** 사용자가 입력을 제출했을 때 **When** 해석이 이뤄지면 **Then** 해석 외의
   목적으로 기록이나 이미지가 외부로 나가서는 안 된다 (FR-ENTRY-15)
2. **Given** 사용자가 자동 해석을 쓰지 않고 직접 기록할 때 **When** 기록이 확정되면
   **Then** 그 기록이 외부로 나가서는 안 된다 (FR-ENTRY-15)
3. **Given** 기록에 근거 이미지가 붙어 있을 때 **When** 그 기록을 조회하거나 요약을 보면
   **Then** 그 과정에서 이미지가 외부로 나가서는 안 된다 (FR-ENTRY-15)
4. **Given** 자동 해석이 실패했을 때 **When** 실패한 뒤의 처리가 이뤄지면
   **Then** 실패한 입력이 해석 외의 목적으로 외부에 남아서는 안 된다 (FR-ENTRY-15)

#### US-09-02 — 나가는 항목 확인하기 (P1)

> **As** 가계부 작성자로서 **I want** 해석을 위해 무엇이 밖으로 나가는지 확인하고
> **So that** 무엇을 맡기고 있는지 모른 채로 쓰지 않는다

- 사용자: 가계부 작성자 · 연계 RFP: FR-ENTRY-16

**수용 조건**

1. **Given** 자동 해석을 쓰고 있을 때 **When** 나가는 항목을 확인하면 **Then** 어떤
   항목이 외부로 나가는지가 제시되어야 한다 (FR-ENTRY-16)
2. **Given** 자동 해석을 쓰지 않을 때 **When** 나가는 항목을 확인하면 **Then** 나가는
   항목이 없음이 드러나야 한다 (FR-ENTRY-16)

## 6. 상태·오류 모델

| 상태 | 사용자 의미 | 제품의 수용 결과 |
|---|---|---|
| 입력 미완료 | 기록이 되기에 필요한 항목이 아직 비어 있다 | 어떤 항목이 비었는지 드러나고, 이미 채운 내용은 남는다. 확정되지 않는다 |
| 권한 부족 | **이 제품에 해당하지 않는다** — 역할이 하나뿐이고 권한으로 나뉜 과업이 없다(§2.3) | 권한을 이유로 막는 상태를 만들지 않는다 |
| 진행 중 | 해석이나 요약이 만들어지고 있다 | 진행 중임이 전달된다. 진행 중을 결과가 없는 것으로 표시하지 않는다 |
| 부분 실패 | 여러 건 중 일부만 해석되었거나 일부 항목만 채워졌다 | 성공한 부분은 유지되고, 실패한 부분이 무엇인지 구분되어 드러난다 |
| 빈 결과 | 조건에 맞는 기록을 찾지 못했다 | 찾지 못했다는 의미로 표시한다. **거래가 없었다는 뜻으로 표시하지 않는다** |
| 처리 실패 | 해석이나 반입 등이 끝내 실패했다 | 실패 사실이 전달되고, 사용자가 적은 내용과 기존 기록이 훼손되지 않는다 |

**빈 결과에 금지되는 해석** — "조건에 맞는 기록 없음"은 "그 기간에 지출·수입이
없었음"이 아니다. 이 제품의 전제 자체가 아직 기록되지 않은 지출이 존재한다는
것이므로(MRD §2), 빈 결과를 부재로 단정하면 사용자의 판단을 왜곡한다.
같은 이유로 "이미지에서 읽어 내지 못함"은 "그 이미지에 내용이 없음"이 아니고,
"예산 미설정"은 "예산 초과"가 아니다.

| 성과 질문 | 확인할 결과 | 현재 검증 상태 |
|---|---|---|
| 기록이 이어지는가 | 쓰기 시작한 뒤 기록이 끊긴 기간의 변화 | 측정 필요 — 사용 기록이 아직 없다 |
| 한 줄로 적는 것이 손으로 넣는 것보다 덜 번거로운가 | 같은 내용을 두 방식으로 남길 때 드는 수고의 비교 | 측정 필요 |

| 배우지 않고 첫 기록에 도달하는가 | 처음 접한 사람이 첫 기록에 이르는 과정 | 측정 필요 (RFP `NFR-ENTRY-06`) |
| 기록이 되짚어 보는 일로 이어지는가 | 요약을 실제로 열어 보는지 | 측정 필요 |
| 분류가 사용자의 기준으로 유지되는가 | 처음 만든 분류가 계속 쓰이는지 | 측정 필요 (MRD 미결 M-05) |
| 기록을 잃을 걱정 없이 쓸 수 있는가 | 반출한 파일만으로 되살아나는지 | 측정 필요 (RFP `NFR-VIEW-03`) |
