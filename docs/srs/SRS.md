## 1. 목적·범위·용어

### 1.1 목적

이 문서는 RFP에서 태어난 `FR-<COMP>-NN`·`NFR-<COMP>-NN`을 **같은 번호로 유지한
채** 관찰·측정·판정 가능한 문장으로 정련하고, 각 요구에 검증 유형을 붙인다.
새 요구 번호를 만들지 않는다.

**"시스템은 ~해야 한다"는 이 문서의 문형이다.** RFP는 같은 요구를 사용자 또는
제품을 주어로 적고(RFP §1·§5), 이 문서가 그것을 시스템이 무엇을 어떤 조건에서
보장하는지로 옮긴다. 두 문서가 같은 문형을 쓰면 한 층이 다른 층의 초벌이 되어
층 하나가 남는다. 이 문서가 더하는 것은 셋이다: 판정할 수 있는 조건, 검증 유형,
그리고 §3이 소유하는 수치 합격선.

### 1.2 문서 경계

| 문서 | 맡는 질문 | 이 SRS와의 경계 |
|---|---|---|
| [MRD](../mrd/MRD.md) | 왜 만드는가 | 문제·범위 방향·제약의 근거 |
| [RFP](../rfp/RFP.md) | 제품이 무엇을 제공해야 하는가 | 요구의 존재와 우선순위, 범위·비범위 |
| [PRD](../prd/PRD.md) | 사용자가 어떤 경험을 얻는가 | 사용자 스토리와 수용 조건 |
| **이 SRS** | 시스템이 검증 가능하게 무엇을 보장하는가 | 같은 번호의 정련·검증 유형·불변조건·인터페이스 계약과 **수치 합격선**(§3) |
| [SDD](../sdd/SDD.md) | 어떻게 구현하는가 | 구조·저장 기술·모듈 구성·기술 선택 이유 |
| [TC](../tc/) | 충족을 어떻게 증명하는가 | 시험 절차·시험 자료·Pass/Fail 전개 |

### 1.3 규범 용어

| 용어 | 의미 |
|---|---|
| SHALL (~해야 한다 / ~해서는 안 된다) | 충족 필수. 미충족은 요구 위반이다 |
| SHOULD (~하는 것을 목표로 한다) | 목표. 제약으로 조정 가능하며 조정 사실을 기록한다 |
| MAY (~할 수 있다) | 선택. 미제공이 위반이 아니다 |

평서문("~한다")은 요구가 아니라 설명이며 §2·§3의 요구 표에 넣지 않는다.

### 1.4 핵심 용어집

| 용어 | 정의 |
|---|---|
| **기록 후보** | 자동 해석 또는 반복 항목으로부터 생성되어 사용자의 확인을 기다리는 미확정 자료. 조회·요약·합계의 대상이 아니다 |
| **확정 기록** | 사용자의 확인 동작을 거쳐 저장된 자료. 조회·요약·합계의 유일한 대상이다 |
| **확인 동작** | 사용자가 기록 후보의 내용을 받아들여 확정 기록으로 만드는 명시적 입력. 화면을 열어 보는 것은 확인 동작이 아니다 |
| **거래 방향** | 기록이 수입인지 지출인지의 구분. 값은 수입·지출·미확정 셋 중 하나다 |
| **분류** | 사용자가 소유하는 기록의 분류 단위. 고유 식별자와 이름을 가지며 이름은 변경 가능하다 |
| **분류 집합** | 특정 시점에 사용자가 보유한 모든 분류의 집합 |
| **태그** | 분류의 **화면 표기 이름**. 요구 문서·저장은 '분류'로 쓰고 화면은 '태그'로 보여 준다. 같은 것을 가리키며, 이 표가 둘의 유일한 대응표다(SDD ADR-012 · ADR-031) |
| **태그 없음** | 확정 기록의 분류 참조가 비어 있는 상태의 화면 표기. 분류가 정해지지 않았음을 뜻하며, '미분류'라는 분류가 따로 있는 것이 아니다 |
| **거래 대상** | 입력에서 추출된, 돈이 오간 상대를 가리키는 문자열(상호명 등). `FR-CAT-07`의 판정 기준이다 |
| **미확정 항목** | 해석이 값을 정하지 못한 항목. 값이 비어 있는 것과 구분되며, 그 사실이 기록 후보에 표시된다 |
| **반복 항목** | 사용자가 등록한, 주기와 기준일을 가진 지출·수입의 정의. 그 자체는 확정 기록이 아니다 |
| **예산** | 분류와 기간을 지정해 저장된 금액 상한 |
| **근거 이미지** | 기록 후보의 생성에 쓰인 이미지. 확정 기록에 참조로 연결된다 |
| **외부 해석 수단** | 입력과 조회 문장의 해석을 수행하는, 제품 밖에서 동작하는 처리 주체 |
| **기기 안 해석 수단** | 제품 안에서 규칙으로 동작하는 해석 수단. 밖으로 아무것도 내보내지 않으며, 외부 해석 수단이 없거나 실패했을 때 이어받는다(`FR-ENTRY-14`). 문장만 다루고 이미지는 읽지 못한다 |
| **대체 처리** | 외부 해석 수단이 실패해 기기 안 해석 수단이 이어받은 상태. 결과와 함께 그 사실과 사유가 사용자에게 전달된다(`NFR-ENTRY-03`) |
| **조회 문장** | 사용자가 무엇을 찾을지 한 줄로 적은 말. 기록을 만들지 않고 조회 조건을 만든다(`FR-VIEW-13`) |
| **조회 조건** | 기간·거래 방향·분류·금액 범위·내용 문자열 가운데 지정된 것들. 지정된 조건을 모두 만족하는 확정 기록만 대상이 된다(`FR-VIEW-06`) |
| **알아들은 조건** | 조회 문장에서 실제로 조건으로 옮겨진 것들의 목록. 조건이 원래 없는 것과 알아듣지 못한 것을 값에서 가르는 근거다 |
| **조회 몫** | 한 조회 문장이 부른 조회 하나. 조회 조건·알아들은 조건·이름을 갖는다. "지출과 수입 따로"처럼 한 문장이 몫 여럿을 부를 수 있고, 몫이 하나면 이름이 없다 |
| **쉬는 날** | 일요일과 대한민국 관공서의 공휴일(대체공휴일 포함). 공휴일은 이름을 갖는다(`FR-VIEW-12`) |
| **첫 진입 지점** | 사용자가 제품에 접근했을 때 최초로 도달하는 지점 |
| **반출 파일** | 확정 기록 전체와 그것을 되살리는 데 필요한 부속 자료(분류·예산·반복 항목·분류 변경 이력·근거 이미지)를 담아 제품 밖으로 내보낸 파일(§7) |
| **삭제된 기록** | 삭제 요청으로 조회·요약 대상에서 제외되었으나 복원 가능한 상태로 보존된 기록 |
| **반복 제시 이력** | 반복 항목이 어느 기간에 이미 후보를 냈는지의 표시. 후보를 받아들이지 않아도 남는다 |

## 2. 기능 요구사항

RFP §5와 같은 그룹 구성을 유지한다. 번호는 RFP와 동일하며, 추가된 것은 관찰
지점과 검증 유형이다.

### 2.1 ENTRY — 기록

| ID | 요구 (검증 가능 문형) | 우선순위 | 검증 유형 |
|---|---|---|---|
| `FR-ENTRY-01` | 시스템은 사용자가 제출한 자연어 입력에 대해 날짜·금액·분류·거래 방향 네 항목 각각에 값 또는 미확정 표시를 담은 기록 후보를 반환해야 한다 | M | 시험 |
| `FR-ENTRY-02` | 시스템은 입력에 포함된 상대적 날짜 표현을 입력 제출 시점의 날짜를 기준으로 확정 날짜로 변환해 기록 후보의 날짜 항목에 반영해야 한다 | M | 시험 |
| `FR-ENTRY-03` | 시스템은 하나의 입력에서 서로 구별되는 거래가 둘 이상 식별될 때 식별된 거래 수와 같은 수의 기록 후보를 반환해야 한다 | S | 시험 |
| `FR-ENTRY-04` | 시스템은 사용자가 제출한 이미지에 대해 `FR-ENTRY-01`과 같은 네 항목 구성의 기록 후보를 반환해야 한다 | M | 시험 |
| `FR-ENTRY-05` | 시스템은 확인 동작이 수행되지 않은 기록 후보를 확정 기록으로 저장해서는 안 된다 | M | 시험 |
| `FR-ENTRY-06` | 시스템은 기록 후보의 네 항목 각각에 대해 확인 동작 이전의 수정 입력을 받아 확정될 값에 반영해야 한다 | M | 시험 |
| `FR-ENTRY-07` | 시스템은 미확정 항목이 있는 기록 후보에 대해 이미 값이 정해진 항목을 유지한 채 나머지 항목의 입력을 받아 확정 기록으로 만들 수 있어야 한다 | M | 시험 |
| `FR-ENTRY-08` | 시스템은 해석 요청 없이 사용자가 직접 입력한 네 항목만으로 확정 기록을 생성해야 한다 | M | 시험 |
| `FR-ENTRY-09` | 시스템은 확정 기록의 각 항목에 대한 수정 입력을 받아 저장된 값을 갱신해야 한다 | M | 시험 |
| `FR-ENTRY-10` | 시스템은 확정 기록의 삭제 요청을 받아 그 기록을 이후 조회·요약의 대상에서 제외해야 한다 | M | 시험 |
| `FR-ENTRY-11` | 시스템은 삭제된 기록의 되살리기 요청을 받아 삭제 직전의 모든 항목 값과 동일한 확정 기록을 복원해야 한다 | S | 시험 |
| `FR-ENTRY-12` | 시스템은 활성 상태인 반복 항목에 대해, 그 주기와 기준일이 지정하는 날짜가 되거나 지난 뒤의 첫 요청 시점에, 그 날짜를 날짜 항목으로 담은 기록 후보를 같은 기간에 한 번만 반환해야 한다 | S | 시험 |
| `FR-ENTRY-13` | 시스템은 이미지로부터 생성된 확정 기록에 대해 그 근거 이미지를 조회할 수 있는 참조를 유지해야 한다 | S | 시험 |
| `FR-ENTRY-14` | 시스템은 외부 해석 수단의 호출이 실패하거나 응답하지 않는 동안에도 `FR-ENTRY-08`의 경로로 확정 기록을 생성해야 한다 | M | 시험 |
| `FR-ENTRY-15` | 시스템은 **해석 요청(입력 해석·조회 요청 해석)** 외의 처리 중에 확정 기록·기록 후보·근거 이미지를 외부로 전송해서는 안 된다 | M | 시험 |
| `FR-ENTRY-16` | 시스템은 해석 요청 시 외부로 전송되는 항목의 목록을 사용자의 조회 요청에 대해 반환해야 하며, 그 목록은 **입력 해석과 조회 요청 해석에서 나가는 항목을 모두** 포함해야 한다 | S | 시험 |
| `FR-ENTRY-17` | 시스템은 첫 진입 지점에서 추가 이동 없이 기록 입력을 시작할 수 있는 수단을 제시해야 한다 | M | 시험 |
| `FR-ENTRY-18` | 시스템은 이미지 첨부 동작이 일어난 시점부터 해석 요청이 이뤄지기 전까지의 사이에, 그 이미지가 외부 해석 수단으로 전송된다는 사실과 민감한 부분을 가릴 수 있다는 안내를 표시해야 한다 | M | 시험 |

### 2.2 CAT — 분류

|---|---|---|---|

| `FR-CAT-02` | 시스템은 분류의 이름 변경 요청을 받아 그 분류의 식별자와 귀속 기록을 유지한 채 이름만 갱신해야 한다 | M | 시험 |
| `FR-CAT-03` | 시스템은 귀속된 확정 기록이 없는 분류의 삭제 요청을 받아 그 분류를 이후 선택지에서 제외해야 한다 | M | 시험 |
| `FR-CAT-04` | 시스템은 사용자가 분류를 하나도 추가하지 않은 상태에서도 분류 집합이 비어 있지 않게 해야 한다 | M | 시험 |
| `FR-CAT-05` | 시스템은 거래 방향이 수입인 기록의 분류 선택지와 지출인 기록의 분류 선택지를 서로 구분해 반환해야 한다 | S | 시험 |

## 4. 시스템 불변조건

어떤 구현에서도 깨지면 안 되는 규칙이다.

1. **확정 기록은 확인 동작을 거친 것만 존재한다.** 확인 동작 없이 생성된 확정
   기록이 존재하면 불변조건 위반이다. (`FR-ENTRY-05`)
2. **조회 결과 0건은 거래의 부재가 아니다.** 시스템은 0건을 부재로 환산해
   표시하거나 계산의 전제로 삼아서는 안 된다. (`FR-VIEW-07`)
3. **자동 배정된 분류는 항상 분류 집합의 원소다.** 분류 집합 밖의 값이 자동
   배정 결과에 나타나면 위반이다. (`FR-CAT-06`)
4. **기록의 분류 귀속은 분류 자체의 변경으로 소실되지 않는다.** 이름 변경·삭제는
   귀속 관계를 끊지 못한다. (`NFR-CAT-01`)
5. **외부 전송은 해석 요청(입력 해석·조회 문장 해석)에서만 발생한다.** 그 밖의
   처리에서 발생한 외부 전송은 위반이다. (`FR-ENTRY-15`)
6. **외부 해석 수단의 가용성은 직접 입력 경로의 가용성을 좌우하지 않는다.**
   (`FR-ENTRY-14`)
7. **기록 후보는 집계의 대상이 아니다.** 합계·요약·예산 대비의 계산에 기록
   후보가 포함되면 위반이다. (§1.4 용어 정의)

| 예산 | 가계부 작성자 | 분류, 기간(월), 금액 | 예산이 저장되고 같은 기간의 지출과 함께 조회된다 | 예산 미설정: 대비할 값이 없다(초과가 아니다) |
| 나가는 항목 조회 | 가계부 작성자 | 없음 | 지금 설정에서 외부로 나가는 항목의 이름 목록과, 항목마다 어느 길(기록 입력·내역 조회)에서 나가는지가 반환된다(`FR-ENTRY-16`) | 외부 수단 미사용: 빈 목록. '나가는 것이 없음'을 그대로 뜻한다 |
| 반출·반입 | 가계부 작성자 | 반출: 이미지를 담을지의 선택(기본은 담는다) / 반입: 이 제품이 만든 형식의 파일 | 반출: 복원용 묶음(§7 '반출 파일') 또는 표 계산용 CSV 가 만들어졌다. **CSV 는 반입 대상이 아니다** / 반입: 파일의 기록이 확정 기록이 됐고, 몇 건을 들여오고 몇 건을 건너뛰었는지가 반환된다 | 형식 불일치·더 새로운 판: 반입하지 않는다. 기존 기록은 훼손되지 않는다 / 겹치는 식별자: 건너뛰고 기존 기록을 갱신하지 않는다(S-08) / 대상 없음: 반출할 기록이 없다(실패가 아니다) |

## 6. 상태·오류·빈 결과의 의미

| 상황 | 시스템 판정 | 사용자에게 표시할 의미 | 금지되는 해석 | 가능한 다음 행동 |
|---|---|---|---|---|
| 입력 해석 결과의 일부 항목이 정해지지 않음 | 미확정 항목 있음 | 어떤 항목이 정해지지 않았는지 | 해석 실패로 단정 / 임의 값으로 채움 | 비어 있는 항목을 채워 확인한다 |
| 입력에서 어떤 항목도 정해지지 않음 | 해석 불가 | 입력에서 기록할 내용을 찾지 못함 | 입력이 잘못됐다고 단정 / 기록할 것이 없다고 단정 | 직접 입력으로 이어받는다 |
| 이미지에서 어떤 항목도 정해지지 않음 | 해석 불가 | 이미지에서 읽어 내지 못함 | 이미지가 잘못됐다고 단정 / 그 이미지에 거래가 없다고 단정 | 직접 입력으로 이어받거나 다른 이미지를 준다 |
| 외부 해석 수단이 응답하지 않음 | 해석 수단 사용 불가 | 지금 자동 해석을 쓸 수 없음 | 기록이 불가능하다고 표시 / 입력을 폐기 | 직접 입력으로 기록한다 |
| 외부 해석 수단이 실패해 기기 안 해석 수단이 이어받음 | 대체 처리 | 외부 해석을 쓰지 못해 기기 안에서 처리했음(사유 포함) | 아무 말 없이 결과만 제시 / 실패로만 표시하고 결과를 감춤 | 결과를 더 살펴 확인하거나, 잠시 뒤 다시 적는다 |
| 첨부 이미지가 허용 형식·크기를 벗어남 | 받을 수 없음 | 어떤 이유로 받지 못했는지(형식·크기·빈 파일) | 이미지에 거래가 없다고 단정 / 함께 적은 문장을 폐기 | 다른 이미지를 주거나 글로 적는다 |
| 조회 문장에서 조건을 하나도 알아듣지 못함 | 알아듣지 못함 | 무엇을 찾을지 알아듣지 못했음 | **조건 없는 전체 목록을 결과로 제시** / 기록이 없다고 단정 | 다르게 적어 다시 묻는다 |
| 조회 결과가 상한을 넘음 | 잘림 | 일부만 보여 주고 있음 | 이것이 전부라고 표시 | 조건을 좁힌다 |
| 확인 동작 없이 이탈 | 후보 미확정 | 아직 기록되지 않음 | 저장된 것으로 표시 | 돌아와 확인하거나 버린다 |
| 조회·검색 결과 0건 | 조건 일치 없음 | 조건에 맞는 기록을 찾지 못함 | **그 기간에 거래가 없었다고 단정** / 합계 0을 "안 씀"으로 단정 | 조건을 바꾸거나 기록을 남긴다 |
| 비교할 기간이 하나뿐 | 비교 불가 | 비교할 기간이 부족함 | 변화가 없다고 단정 | 기간을 넓힌다 |
| 예산이 설정되지 않음 | 대비 대상 없음 | 이 분류·기간에 예산이 없음 | **예산 초과로 표시** / 예산 0으로 계산 | 예산을 정한다 |
| 귀속 기록이 있는 분류의 삭제 시도 | 확인 필요 | 그 분류에 기록이 남아 있음 | 확인 없이 삭제 / 귀속 기록을 함께 삭제 | 확인 후 진행하거나 그만둔다 |
| 삭제 후 복원 대상 없음 | 대상 없음 | 되살릴 기록이 없음 | 다른 기록을 복원 | 그만둔다 |
| 반입 파일의 형식 불일치 | 반입 불가 | 이 파일로는 반입할 수 없음 | 부분 반입 / 기존 기록 훼손 | 다른 파일로 시도한다 |
| 반입 파일이 이 제품이 아는 것보다 새로운 판 | 반입 불가 | 더 새로운 형식이라 읽을 수 없음 | 부분 반입 / 아는 부분만 골라 반입 | 제품을 갱신한 뒤 다시 시도한다 |
| 반입 파일에 이미 있는 기록이 섞여 있음 | 일부 건너뜀 | 들여온 수와 건너뛴 수 | 기존 기록을 덮어씀 / 실패로 표시 | 그대로 쓴다 |
| 반출할 기록 없음 | 대상 없음 | 반출할 기록이 없음 | 반출 실패로 표시 | 기록을 남긴 뒤 반출한다 |

**금지되는 해석의 근거** — 이 제품은 "아직 기록되지 않은 지출이 존재한다"는
전제 위에 있다(MRD §2). 0건을 부재로 환산하는 순간 사용자의 판단이 왜곡되므로,
이는 표시 문제가 아니라 §4 불변조건 2의 문제다.

## 7. 데이터 논리 계약

저장 기술과 무관하게 보존되어야 하는 식별·귀속·참조 관계다. 물리 스키마·색인은
SDD가 소유한다.

| 자료 | 보존해야 하는 것 |
|---|---|
| 확정 기록 | 고유 식별자 · 날짜 · 금액(양수 정수) · 거래 방향 · 분류 참조(없을 수 있음, '태그 없음') · 사용자가 적은 내용 · 거래 대상(없을 수 있음) · 근거 이미지 참조(없을 수 있음) · 확정 시각 · 마지막 수정 시각 |
| 기록 후보 | 확정 기록과 **분리된 자료**로 존재하며, 항목별로 값 또는 미확정 표시를 가진다. 확정 기록의 식별자를 가지지 않는다. 함께 보존하는 것: 사용자가 적은 원문(해석이 실패해도 남는다, `FR-ENTRY-07`) · 어느 경로(문장·이미지·반복 항목·직접)에서 왔는지 · 어느 해석 수단이 만들었는지 · **해석이 처음 제안한 분류**(사용자가 바꿨는지를 `FR-CAT-07` 이 이것과 견주어 판정한다) |
| 분류 | 고유 식별자 · 이름 · 적용되는 거래 방향 · 차례 · 처음 제공된 것인지 · **보관 표시**. 삭제는 행을 지우지 않고 보관 표시로 한다. 선택지에서만 빠지고 귀속은 남는다(`NFR-CAT-01`). 이름 중복 금지는 같은 거래 방향의 보관되지 않은 분류 안에서만 적용된다 |
| 기록→분류 참조 | **이름이 아니라 식별자로 유지된다.** 이름이 바뀌어도 참조가 끊기지 않아야 한다(`NFR-CAT-01`) |
| 삭제된 기록 | 삭제 표시와 삭제 직전의 모든 항목 값. 되살리기가 값을 재구성하지 않고 복원할 수 있어야 한다(`FR-ENTRY-11`) |
| 반복 항목 | 고유 식별자 · 주기(월) · 기준일(그 달의 며칠. 그 달에 없는 날이면 그 달의 마지막 날로 당긴다) · 활성 여부 · 생성할 기록의 내용(이름·금액·거래 방향·분류·내용·거래 대상). 반복 항목과 그로부터 확정된 기록은 서로 다른 자료다 |
| 반복 제시 이력 | 반복 항목 식별자 · 기간. 어느 기간에 이미 후보를 냈는지의 표시이며, 사용자가 후보를 받아들이지 않아도 남는다(PRD US-04-01 수용 조건 3) |
| 예산 | 분류 참조 · 기간(월) · 금액. 예산의 부재와 금액 0은 서로 다른 상태다 |
| 분류 변경 이력 | 거래 대상 문자열 · 사용자가 선택한 분류 참조 · 기록 시각. `FR-CAT-07`의 판정 근거이며, 같은 거래 대상에 대해 가장 나중의 것이 우선한다. 거래 대상은 앞뒤 공백을 떼고 대소문자를 통일한 뒤 **완전 일치**로 견준다(S-06). 보관된 분류를 가리키는 이력은 배정에 쓰지 않는다(`FR-CAT-06`) |
| 근거 이미지 | 고유 식별자 · 형식 · 크기 · 보관 위치 참조. 확정 기록당 하나 이하로 연결된다. 이미지의 삭제가 기록의 다른 항목을 훼손해서는 안 된다 |
| 반출 파일 | 형식 표지 · 판 번호 · 반출 시각 · 분류 전체(보관된 것 포함) · 확정 기록 전체(삭제 표시된 것 포함. 되살리기가 반입 뒤에도 성립한다) · 예산 · 반복 항목 · 분류 변경 이력 · 근거 이미지 원본(담지 않는 선택이 있으나, 그때는 `NFR-VIEW-03` 이 이미지에 대해 성립하지 않는다) |

## 8. 비목표와 호환 경로

- **현재 요구가 아닌 것** — RFP §3.2의 비범위를 그대로 따른다. 이 문서는 비범위를
  새로 만들지 않는다.
- **호환 경로** — 이전 버전이 없는 최초 명세이므로 과거 호환 대상이 없다. 반출
  파일에는 **형식 표지와 판 번호**가 있고, 반입은 자신이 만든 형식 표지이면서 판
  번호가 지금 제품이 아는 것 이하일 때만 받는다(`FR-VIEW-11`). 더 새로운 판은
  반입하지 않는다. 판이 오르면 그 시점의 이전 판에 대한 처리 방침을 이 절에 추가한다.
- **표 계산용 CSV 는 반입 대상이 아니다.** 복원용이 아니라 밖에서 열어 보기 위한
  것이며, 삭제된 기록과 근거 이미지를 담지 않는다. 복원은 반출 파일만이 맡는다.

## 9. 제약과 가정

| 구분 | 내용 | 근거 | 깨지면 무효가 되는 요구 |
|---|---|---|---|
| 제약 | 금융기관의 거래 내역을 자동으로 수집하지 않는다 | MRD §6.1 (신용정보법 제4조) | 해당 없음. 이 제약이 `FR-ENTRY-01`·`FR-ENTRY-04`의 존재 이유다 |
| 제약 | 사용자는 한 사람이며 역할·권한 구분이 없다 | RFP §3.2 | `FR-ENTRY-09`, `FR-ENTRY-10`, `FR-CAT-03`. 다수 사용자가 되면 누가 고치고 지울 수 있는지가 새 요구가 된다 |
| 제약 | 확정 기록과 근거 이미지는 사용자 기기 안에 보관된다 | RFP §7.1, `NFR-ENTRY-05` | `NFR-ENTRY-05`, `NFR-VIEW-03` |
| 제약 | 외부 해석 수단의 이용 조건·한도는 제품이 통제할 수 없다 | MRD §6.2 | `NFR-ENTRY-01`. 한도 초과 시 경과 시간의 의미가 달라진다 |
| 가정 | 입력 제출 시점의 기기 날짜가 정확하다 | 상대적 날짜 해석의 기준 | `FR-ENTRY-02`, `FR-ENTRY-12`. 기기 날짜가 틀리면 해석 결과가 요구를 만족해도 사용자에게 틀린 날짜가 된다 |
| 가정 | 사용자가 적는 금액의 통화는 하나이며 환산이 필요 없다 | RFP §3.2(외화 비범위) | `FR-VIEW-03`, `FR-VIEW-04`, `FR-VIEW-09`. 통화가 섞이면 합계의 의미가 성립하지 않는다 |
| 가정 | 같은 거래 대상 문자열은 같은 상대를 가리킨다 | `FR-CAT-07`의 판정 기준(§1.4) | `FR-CAT-07`. 다른 상대가 같은 이름을 쓰면 잘못된 분류가 반영된다 |
| 가정 | 반출 파일은 제품 밖에서 변형되지 않은 채 돌아온다 | `FR-VIEW-11`의 입력 전제 | `FR-VIEW-11`, `NFR-VIEW-03` |
| 가정 | 자동 해석의 정확도가 낮아도 사용자가 확인 단계에서 교정한다 | RFP §8 수용 원칙 4 | `FR-ENTRY-01`, `FR-ENTRY-04`. 이 가정이 깨지면 정확도가 수용 조건이 되어야 한다 |
| 제약 | 기기 안 해석 수단은 이미지를 읽지 못한다 | §1.4. 규칙 기반은 문장만 다룬다 | `FR-ENTRY-04`. 외부 해석 수단을 쓸 수 없는 동안 이미지 입력은 해석되지 않고 `FR-ENTRY-07` 의 이어받기 경로로만 기록된다 |
| 제약 | 쉬는 날의 표는 제품 안에 있고, 음력에서 오는 공휴일은 표가 아는 해에 대해서만 안다 | `FR-ENTRY-15`. 공휴일을 밖에 물어보면 나가는 지점이 늘어난다 | `FR-VIEW-12`. 표가 모르는 해에는 그 공휴일이 표시되지 않는다. 해마다 표를 갱신해야 한다 |
| 가정 | 외부 해석 수단의 모델은 공급자 사정으로 바뀔 수 있고, 모델이 다르면 같은 문장도 다르게 읽을 수 있다 | MRD §6.2 | `NFR-ENTRY-02`. 측정 결과는 어느 모델로 측정했는지와 함께 남겨야 뜻이 있다 |
